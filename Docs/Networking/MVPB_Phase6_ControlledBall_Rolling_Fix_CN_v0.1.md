# MVP-B 阶段 6：客户端持球滚动表现修正（v0.1）

日期：2026-09-26。状态：**C++ 修复已写入；Editor/Game Target 编译通过，自动化 12/12 通过。双进程可见滚动表现待团队复测，阶段 6 未验收。** 本文接续 `MVPB_Listen_Phase6_Implementation_CN_v0.2.md`，只处理客户端 `Controlled` 球缺少滚动表现的问题。

## 现象与原因

团队观察到：客户端窗口里，不论由主机还是客户端车辆持球，球的位置会正确跟随车辆，但球的表面不再滚动。`Free`／`Launched` 的服务器权威物理及球权状态没有被报告异常。

v0.2 为了让客户端无碰撞的球根组件和调试球形跟随车辆，在每次 PostPhysics Tick 中同时把球的位置、旋转设为 `BallControlPoint` 的位置、旋转。这样车辆姿态覆盖了球的自转，视觉 Mesh 作为根组件子物体也就失去了滚动。此问题属于客户端表现，不应通过恢复客户端球碰撞或改变服务器球物理来修复。

## 修正与边界

- 仅客户端且仅 `Controlled` 时：球根组件仍然关闭模拟和碰撞，位置继续跟随 `BallControlPoint`。进入状态时保存球已有的显示旋转；之后用控制点每帧的**水平位移**计算滚动轴和角度，角度为 `位移距离 / 当前球碰撞半径`，逐帧累计并归一化显示旋转。第一次拿到目标位置只初始化轨迹，不让首帧的位置跳变造成一次巨大的假滚动。
- 客户端根组件的旋转不再被车辆朝向每帧覆盖；其附属视觉 Mesh 与调试形状随之旋转。离开 `Controlled` 时停止表现 Tick、恢复球体模拟和碰撞，后续仍由服务器物理复制与 PI 管理。
- 不变更服务器持球约束、球权序号、发射/命中规则、车辆或球 Data Asset 数值，也不增加 Blueprint Event Graph。这里计算的是显示用滚动，不是客户端上报的物理角速度。

## 复测

完全退出旧 PIE／Standalone 与 Editor 后，打开用修正版 C++ 编译的项目。保留现有 `BP_BasicBall`、`DA_NetworkPhysics_Ball_MVPB` 和 `MVPB_NetTest` 接线，不必重填或重新保存这些资产。双进程 Listen Server 中由主机 `HALStartMatch` 后，分别让主机与客户端车辆持球：

1. 在**客户端窗口**连续直行、倒车、转向，并观察两辆车持有的球。球应跟随车头且表面持续滚动；倒车时滚动方向反转，停车后不应无故持续转动。
2. 临时开启客户端物理调试形状，确认球根组件与可见球一起移动，没有停在拾取点；关闭调试后观察正常视觉效果。
3. 发射、脱球后球应恢复其服务器物理复制下的运动；留意切换瞬间是否出现明显旋转跳变。先在低延迟复测，再在约 100 ms 实测 RTT、1% 丢包、20 ms 抖动下复测。

若表面仍像静止，先确认球视觉 Mesh／材质上有可辨方向的图案；纯色球即使旋转也可能看不出。使用原有可辨识材质或 Editor 视图调试即可，不要为验证滚动修改权威物理参数。若正常纹理仍不滚动，保存客户端短视频与两端日志。
