# MVP-B 阶段 6：服务器权威捕球轨迹与运动规则复盘（v0.2）

日期：2026-09-26。状态：**本版实测失败，已由 `MVPB_Phase6_AuthoritativeCapture_CN_v0.3.md` 修正；不能用于验收。** 本版虽然编译与自动化通过，但团队双进程实测发现客户端持球球体停在原地，并有约 1 秒画面卡顿。`HAL_Future_Creation_2.log` 明确记录 `Invalid Simulate Options` 与 `PhysicsRoot->IsSimulatingPhysics()` Ensure：`NoCollision` 销毁了球的 Chaos 物理状态，使 PI 无法消费服务器刚体复制。以下保留原始设计记录，修正与验收以 v0.3 为准。本文接续 `MVPB_Listen_Phase6_Implementation_CN_v0.2.md`。上一版 `MVPB_Phase6_ClientCaptureBlend_CN_v0.1.md` 的固定时长客户端插值已撤销。

## 本次改动

原实现收到 `Controlled` 后关闭客户端球刚体模拟，并在 PostPhysics Tick 将球根组件直接移动到车辆 `BallControlPoint`；后加的 0.18 s 平滑仍是另一条本地生成的位置路径。服务器真实球却被 Chaos 约束拉向控制点。两端吸入轨迹的来源不同，客户端因此先瞬移，后虽可平滑但仍不与服务器一致。

现在客户端在 `Controlled` 期间保持球刚体模拟及球 Actor 原有的物理运动复制和 **Predictive Interpolation（PI）**。服务器约束产生的球位置、速度、旋转经既有复制流到达客户端，由 PI 呈现；不再用控制点或本地固定曲线生成球的位置和滚动。客户端在持球时关闭本地球碰撞与重力，不创建本地约束，因此不会把非权威球反力传给车辆；离开 `Controlled` 后恢复蓝图/DA 配置的碰撞和重力。服务器仍只运行既有球约束、球权与碰撞规则。没有新增逐帧 RPC、Data Asset 字段、蓝图接线或资产路径。

这是**共享权威轨迹，保留不同网络显示方式**，不是把客户端变成另一台碰撞裁判。客户端在 RTT 下会晚于服务器看到吸入，PI 也可能平滑或短暂修正；它不承诺逐帧与主机画面像素一致。若现有 PI 设置不足以平顺呈现短促吸入，应先记录两端视频和实际 RTT，再评估球的复制频率与球专用 Network Physics DA；不得用车辆动力或碰撞调参掩盖。

## 本阶段车辆／球运动规则复盘

| 对象与状态 | 服务器规则 | 客户端执行／呈现 | 对未来冲击与碰撞效果的影响 |
|---|---|---|---|
| 主机车辆 | 同一 `SimulateVehicleStep` 力/转向公式，Chaos 权威碰撞 | 主机即服务器，无网络回放 | 改驾驶力参数会改变权威结果，应继续由 VehicleDefinition 提供唯一基线。 |
| 客户端自有车辆 | 消费网络输入历史，在服务器 Chaos 执行同一 `SimulateVehicleStep` | 用同一移动代码本地预测、Resimulation 校正；本地碰撞环境可能暂时与服务器不同 | 力公式相同，接触时间与对象位置未必相同。提高撞击/击退强度可能放大回退修正，需做延迟碰撞测试。 |
| 客户端看到的远端车辆 | 服务器执行其输入和 Chaos 碰撞 | 不执行远端驾驶力；用服务器物理状态 PI 呈现 | 远端受击由服务器决定并复制，视觉到达受 RTT/PI 影响；不能用远端本地 Hit 回调作伤害依据。 |
| `Free`／`Launched` 球 | 服务器 Chaos、碰撞、命中与伤害结算 | 球物理状态复制 + PI；客户端物理接触不能结算伤害 | 球反弹/命中应以服务器为准；增大冲量时客户端可见轨迹可能需要更多平滑或修正。 |
| `Controlled` 球（本次后） | 服务器约束驱动真实球；车辆为约束父端，不接受球的不可预测反力 | 不建约束、无本地球碰撞/重力；球继续模拟并消费服务器物理复制 + PI | 吸入轨迹来自服务器；客户端没有相同的约束模拟，仍不能预测持球球体与环境的权威冲击。 |
| 发射反作用力、脱球和球命中击退 | 仅服务器触发冲量/速度变更及规则事件 | 当前由随后权威车辆/球状态纠正或呈现；发射动作的帧对齐预测属于阶段 7 | **这里仍有手感风险**：若把更强冲量直接加在客户端本地碰撞回调，可能与服务器重复或分叉。要预测就把动作序号、物理帧与回滚状态纳入历史，并保持服务器一次性裁决。 |

**结论：** 客户端和服务器并非所有刚体都运行完全相同的底层流程；自有车辆的移动公式统一，而远端车和球依服务器状态呈现，这属于设计中的权威／预测分工。本轮消除了捕球时客户端自行生成另一条位置曲线。未来统一“冲击力的规则”应统一权威命中上下文、参数、动作序号与结算入口，不能要求所有客户端对碰撞瞬间作出完全相同的独立物理判定。对预测性反作用力和强击退，须额外验证历史重放、接触修正与表现事件去重；当前阶段未宣称这些已完成。

## 团队复测与留档

无需重建 `BP_BasicBall` 或重填 Data Asset。关闭旧 PIE/Standalone 与 Editor，以新编译的 C++ 打开 `/Game/Maps/MVPB_NetTest`，运行双进程 Listen Server；主机 `HALStartMatch`。保持 **Use Less CPU when in Background** 关闭。

1. 分别由主机、客户端车辆捕获静止球和正在滚动的球，在**两个窗口**录下球从原位置靠近车头的过程。客户端不能瞬移、停在原地或出现自定义固定时长的“第二条吸入曲线”；可允许因 RTT/PI 晚到与轻微修正。检查调试球形随可见球移动、球面继续滚动、持球车辆不回拉。
2. 在吸入中加速、倒车、转向、贴墙、立即发射或被撞脱球。观察两端最终球状态/位置一致，客户端球不穿墙造成权威效果，发射后继续由 PI 呈现。重捕获至少数轮。
3. 先低延迟，再约 **100 ms 实测 RTT、1% 丢包、20 ms 抖动** 复测。若球短促吸入被 PI 平滑得几乎不可见，记录视频、球 DA 的 `Sim Proxy Rep Mode`、两端日志与 RTT；不要先更改约束力或车体冲量。
4. 为未来冲击力基线，各做一次两车正撞/侧撞/墙角连续接触、自由球反弹、发射球命中，以及持球中脱球。记录本地车大幅修正、远端车震荡是否超过 1 秒、命中/脱球是否只结算一次。正式冲击效果改动前用同一组场景再比较。

可暂时在两端执行 `hal.BallNetLog 1` 观察 `StateSequence`/Holder，结束后设回 `0`；物理调试可用 `p.Chaos.DebugDraw.Enabled 1`、`p.Net.DebugDraw.ShowRepMode 1`，结束后关闭。若客户端持球球形不显示 PI 或球不动，先保存日志与截图，不要修改蓝图资产来补做本地约束。
