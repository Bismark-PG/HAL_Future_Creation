## 1. 权威与采样

- `BasicBallActor`新增原生默认子组件`HALBallPresentationComponent`。既有服务器球约束、球状态、捕获／发射许可、伤害与运动复制保持。
- Controlled时服务器注册一个PostSolve回调，直接读取同一步的球和持有车刚体已求解位置／旋转／速度。物理线程不读取UObject、蓝图、DA、GAS或GT Transform；相对坐标为不重复应用车型Scale的车体坐标，单位cm。相对线速扣除持有车平移及旋转贡献，保留相对角速以呈现滚动。
- GT在PostPhysics消费样本，以20Hz上限复制`StateSequence＋Holder身份＋PhysicsFrame＋ServerPublishSeconds＋相对姿态／速度`，首个有效样本尽快发布。不是每渲染帧RPC，也不在车辆上增加另一份球权。该Holder／序号只用于与原球状态匹配。
- 状态／持有者变化时，先撤销并排空在途采样回调，再移除；退出及组件注销也清理，避免旧球权数据读取已销毁持有者。

## 2. 客户端显示与交接

- 可见网格使用“当前持有车显示变换 × 平滑后的权威相对变换”。自己的车沿现有预测／纠正姿态，远端车沿现有插值姿态；不修改车辆或球的物理根。
- 样本须同时匹配 `Controlled`、当前持有车和本次持有序号。首次进入需要新鲜样本。相对速度最多外推 0.1 秒。样本过期时，已绑定的同一次持有可再等一个 `Stale Seconds`，期间保留最后显示的车体局部位置和旋转，每帧按当前车身姿态显示。重复或乱序包不会延长等待时间。
- 仅对 `VisualMesh` 临时使用世界位置和旋转。首次进入和短时断样恢复均在车身局部坐标平滑过渡。客户端一旦确认发射、脱球、换持有者或持有者失效，立即结束旧球权的相对跟随。超过完整等待期限或关闭相对显示时同样开始向物理根交接，随后恢复网格原有偏移、旋转、缩放与父级。
- Controlled客户端仍保留Chaos物理状态、Ignore碰撞响应、关本地重力；退出Controlled后由原Actor逻辑恢复。没有NoCollision销毁刚体、Attach真实球、SetActorLocation或新客户端约束。
- Host／Standalone画面继续直接显示服务器球；本次不消除球权首次确认、真实发射的往返等待，也没有实现假球发射、客户端命中或全局球Resimulation。异常网络下回退PI仍可能出现可见校正，不能承诺任意丢包下像素一致。

## 3. 配置与开关

原球DA新增`Presentation`结构。旧保存资产缺省读新字段默认值，既有物理／伤害／控球参数不覆盖；**无需创建新DA或改蓝图Event Graph**。新配置仅影响表现，原生运行时若其无效会记录Warning并回退PI，不阻止车辆／球物理；Editor资产Validate同时检查这组值。

| 字段 | 默认值 | 说明 |
|---|---:|---|
| Enabled | true | 启用本轮相对显示 |
| Send Rate Hz | 20 | 服务器样本复制上限，5～60 |
| Relative Blend Seconds | 0.05秒 | 权威相对姿态的平滑响应时间 |
| Handoff Seconds | 0.12秒 | 出入相对显示的有界交接 |
| Stale Seconds | 0.5秒 | 样本新鲜期。已绑定同一球权时再保留一个等长窗口，默认样本年龄超过 1.0 秒开始回到物理根 |
| Maximum Extrapolation Seconds | 0.1秒 | 相对速度外推上限，不大于Stale |
| Maximum Relative Distance | 2000cm | 仅表现数据安全范围，不改变捕获／脱球距离 |

客户端控制台`hal.BallRelativeVisual 0`返回原PI显示，`1`启用，供同场A/B；不改服务器约束或球权。`hal.BallPresentationLog 1`输出模式变化和每秒一次的帧／样本／年龄计数，结束设0。原`hal.BallNetLog`、`hal.VehicleNetLog`继续用于状态和发射许可诊断。

## 4. 团队Editor步骤与手测

1. 保存需要保留的资产并关闭旧游戏／Editor；完整重编后重开。打开`BP_BasicBall`的组件列表，确认新增原生`Ball Presentation`存在即可，无需拖组件或接Event Graph。
2. 打开实际球Definition，保留已有Visual、Physics、Gameplay数值；新增Presentation可直接先用默认值。只有调整时才手动保存／Validate该DA，全部参与电脑同步同一代码／配置并重启游戏。代理不保存这些资产。
3. 按原菜单或命令行启动 Listen Host 与客户端进入 NetTest，由 Host 开始。两端开启 `hal.BallNetLog 1`、`hal.VehicleNetLog 1`、`hal.BallPresentationLog 1`。持球时 Host 的 Published 和客户端的 Received 应持续增长。客户端 Mode 1 表示按新鲜样本随车，3 表示短时缺样继续随车，2 表示正向物理根交接，0 表示由物理根显示。同时可用 `stat unit` 和 `stat net` 记录帧耗与网络状况。
4. 主机持球后直走、急转、加速／减速／倒车，再换客户端持球；在客户端分别观察自己的球和别人球。短时切`hal.BallRelativeVisual 0/1`比较转弯时车球错位，不能改质量／约束或关闭其他网络规则来做对比。
5. 观察实际吸入过程和球面滚动；测试吸入中立即发射、快速重复发射、脱球／重捕、持球撞墙、外部打断及持有者退出。球进入Free／Launched后必须退出相对显示，回到原球运动；不得留下可见球挂在车头或瞬间跳回旧根位置。
6. 检查网络抖动／样本过期、球权切换及引用晚到时能回退并恢复。客户端碰撞调试球形代表物理根PI位置，可与相对可见网格暂时不同，不能拿可见网格反向驱动命中；Host物理判定仍为准。
7. 基础双端后按当前四台学校有线环境复测，记录版本、Host帧时间、Ping和视频。当前改造是针对车球时间线错位，若仍有明显延迟，保留诊断继续区分Host／传输／相对偏移迟到。完整F4、VP复杂组合与四机长时验收不因本步自动关闭。

## 7. 2026-11-18 持球漂移时的复制和显示修复

持球时，服务器对每个观察连接分别计算球的复制优先级。权重下限是球原有优先级乘以 4，再乘该连接距离上次更新的时间。快速甩头时，即使车头偏离观察方向，持有球仍能竞争发送机会。发射或脱球后，已有连接在第一次获得更新机会前继续享受这个优先级，随后回到普通球的调度。实际到包时间仍受网络状况影响。

客户端只对已经显示过的同一辆车、同一次持有保留相对位置。默认样本年龄在 0.5～1.0 秒之间时，车继续转弯，球会跟着转，同时停止更新球相对车身的偏移。若新样本及时到达，默认用 0.12 秒在车身坐标内平滑接回。若持续断样超过 1.0 秒，或已收到发射、脱球、新球权，客户端结束旧跟随。新的持有需要自己的有效样本。

本机 UE 5.8.3（CL 58210709）的 Win64 Development Editor 与 Game 目标均构建成功。`HAL.FutureCreation` 原生回归执行 248 项，246 项通过且零警告，2 项通过并记录测试车辆配置警告，0 项失败。球相关用例覆盖转弯断样、停止相对外推、恢复首帧的连续性、长断样、发射、掉球、重捕、换持有者后旧包晚到和持有者销毁，并核对显示处理未移动物理根。

以下各轮都使用项目默认发送预算、独立无画面 UE 游戏进程和 Host 出站 80 ms 模拟延迟。两辆车分别持球并转弯约两秒后发射。“样本”是驾驶客户端在发射输入前检查点累计接受的本车球／远端车球姿态数。“误交接”从首次成功随车开始计数，到客户端确认离开本次持有为止。

| 场景 | 样本 | 持球中误交接 | 发射后的显示 |
|---|---:|---:|---|
| 双端，第 1 轮 | 29 / 29 | 0 | 两球均回到物理根 |
| 双端，第 2 轮 | 32 / 33 | 0 | 两球均回到物理根 |
| 双端，第 3 轮，开启逐 Actor 复制日志 | 33 / 33 | 0 | 两球均回到物理根 |
| 一主三客，两名驾驶者加速转弯后按住手刹，另两名玩家观察 | 27 / 28 | 三个客户端均为 0 | 三个客户端的两球均在收到发射后回到物理根 |

三轮双端与四进程场次的 Host、驾驶 Client 专项均为 1/1，通过且零测试警告。四进程场次的两个观察客户端分别在发射交接时累计收到两球 23 / 21 和 31 / 33 个样本，结果来自各自的状态与显示日志。逐 Actor 复制日志对照中，从首次捕获至首次发射，两颗持有球各自相邻调度尝试的最长间隔由修复前的 559 / 142 ms 降为本次的 93 / 111 ms。该间隔由单场 Host 日志测得，实际网络收包间隔另受传输影响。

本机日志与报告位于 `Saved/BallClientReview/`。构建与原生回归对应 `Fix_Editor_Final.log`、`Fix_Game.log`、`Fix_Native/index.json`。前三轮对应 `Pair_20261118_194029`、`194457`、`194606`，四进程对应 `Four_20261118_194155`。复现四人用例时先让两个普通观察客户端加入 NetTest Listen Host，最后加入驾驶客户端。只在 Host 和驾驶客户端运行 `HAL.NetworkSmoke.BallRelativePresentation` 并加启动参数 `-HALBallDrift`，所有客户端开启 `hal.BallPresentationLog 1` 与 `hal.BallNetLog 1`。

学校验收仍需四台机器使用同一构建，各录一次自己持球连续漂移和观察别人持球连续漂移，再各做一次发射、撞击脱球。若仍有跳位，保存 Host 和出现问题的 Client 的同场日志和录像时刻，对齐球权序号、显示模式和样本年龄。红色线框的开关在球定义的 `Physics → Hidden In Game`，由用户调整。
