# GF-7基础比赛闭环：已确认规格 v0.1

日期：2026-11-05，Asia/Tokyo。只读核对基点：干净`main/726b804`，本机UE5.8.3-58210709。用户已确认并列／全灭、退场观战、8秒结算返房及Client弃权继续四组规则，并授权完整开发；全部UI继续原生回退＋Widget Blueprint可替换。当前实现与测试状态见[实施文档](GF7_Match_Loop_Implementation_CN_v0.1.md)。

## 1. 当前实际基础与缺口

已完成：选车／确认、权威名单锁定、正式场地跨图、客户端加载屏障、共同倒计时、Playing、手动返回原练习房间、重新确认／下一局及Avatar／效果／物理历史清理。

未完成：正式比赛截止时间、存活／淘汰名单、HP归零退出比赛、观战、最后存活者／超时比较、结果快照、结算界面和自动返房。`EHALMatchPhase`只有WaitingForPlayers／Playing；Room Phase没有Results。Health可到0，但尚无权威淘汰状态和对应操作限制链路。

现有`ReturnActiveRoundToRoom()`只接受Playing；需要将其共用返房执行路径接到正式结束／结果阶段，同时保留手动测试中止的语义。现有`Logout()`在正式World参与者退出后让全员返房，不能直接当成弃权继续比赛。动态相机目前只为本地受控Pawn计算，观战需独立本地视角适配，不能靠接管其他玩家车辆或绑定他人ASC实现。

GF-1～6原先明确后置正式比赛规则；本次是用户提出的新开发范围，不把旧阶段的完成记录扩写成这些规则已经实现。

## 2. 推荐闭环

```text
房间选车确认 → 加载正式场地 → 全员就绪 → 共同倒计时
→ Playing（开始比赛计时）
→ HP归零淘汰／仅剩一人／时间到
→ Results（冻结裁决，显示结果）
→ Returning → 原练习房间重新选车确认 → 下一局
```

- 沿用AGENTS既定默认：300游戏秒，只从正式Playing开始计时；加载、开赛倒计时、练习房间不计入。每位玩家的本地菜单不暂停服务器比赛。
- 服务器保存截止时间，客户端以同步服务器时钟显示剩余时间，不各自递减或上报胜负。
- HP归零后，本局不可恢复为参赛者；停驾驶／击球／技能／自救，释放持球，清理当前Pawn作用域与区域成员状态，再切观战。
- 至少两名参赛者开局时，仅剩一名存活者立即触发胜利条件。单人Development不触发“开局只剩一人”立即获胜，仍可独自测试计时和结果；0名存活者可结束为平局。
- 时间到，只比较仍存活且未弃权者的**剩余绝对HP**，不是HP百分比；这是既有规则。若将来车型MaxHP差异较大，公平性调优另作规则变更，不悄悄切换公式。
- 同一服务器结算批次的淘汰集中处理后再判断胜负，避免按碰撞／属性回调先后误判；时间截止与伤害同帧也由统一服务器入口确定有效伤害和结果。
- 结束只执行一次，以FlowId／RoundId保护迟到回调。冻结胜者、结束原因和各玩家最终状态／HP快照；后续残留事件不能改写结果。结束后关闭新伤害与玩法操作。

## 3. 四组已确认规则

| 项目 | 推荐默认 |
|---|---|
| 并列与同时淘汰 | 超时最高HP并列者共同获胜；最后存活者在同一结算批次全部淘汰则为平局 |
| 淘汰后的车辆与观战 | 车体退场，不保留参与碰撞的残骸；玩家自动跟随存活车辆，可通过简单左右按钮切换，目标淘汰后自动换下一个；无目标时使用场地俯视兜底 |
| 结算与返回 | 显示8秒结果后由服务器统一返回原练习房间；Host可提前返回。结果展示时长可调；返回后保留身份／席位／颜色／车型偏好，清除确认，下一局按已有流程重建并满血 |
| 中途退出 | Playing中普通Client退出按弃权处理，其余人继续；Loading／Countdown中有人退出仍取消本次开赛并恢复房间；Host进程退出仍全员回入口。Host仅被淘汰时继续承担服务器并观战 |

比赛300秒、结果展示8秒及必要观战参数放在配置中；比赛规则优先加到现有Room Config的Match Rules配置结构，不散落在UI和关卡蓝图。临时测试可设短时长，不必每次等5分钟。

## 4. 职责与接口边界

- GameMode：权威名单、HP通知订阅、比赛计时／统一裁决、淘汰和结果到返房的编排。使用事件和定时器，不新增Gameplay Ability Tick。
- GameState／Room：同步截止时间、回合阶段、参赛状态与结果快照，以现有回合状态链为准；旧MatchPhase保持兼容，不建立互不一致的双状态机。
- PlayerState：本局存活／淘汰／弃权身份，保留结果所需稳定PlayerKey／编号／名字等；不靠Pawn是否存在隐式推断胜负，不把战绩永久累计到本次范围。
- Controller：本地观战目标与菜单输入，只有服务器允许的退出／返房请求；观战不接管他人Pawn，不修改他人ASC。
- UI：原生倒计时、淘汰／观战提示、简易结果页作为回退，并补只读快照／事件／语义动作供Widget Blueprint覆盖。继续遵守Designer优先。
- 跨图：结果使用值快照，不能把旧World的Pawn／Controller引用带回房间。复用GF-4／GF-6身份与返房清理链路。

手动开发／展示测试返回仍属于中止，不伪造正常胜者；已完成比赛的正常返房不依赖`-HALAllowTestRoundEnd`。不新增Host迁移、断线重连、加时玩法、复杂战绩系统或演出框架。

## 5. 推荐实施顺序与验证

1. 配置与权威数据：截止时间、参赛状态、结果结构、阶段／权限与确定性裁决。先用短时长和合成事件检查最后存活、超时、并列、全灭与重复结束。
2. 淘汰与观战：HP事件、车体／球权／技能清理、本地观战及目标切换、Client弃权、Host淘汰。验收旧车不能继续操作、观战不能控制对方、迟到事件不污染下一局。
3. UI和返房集成：计时／结果／观战原生回退与WBP接口、8秒自动返房及Host提前返回；实际Listen Host／Client连续两局与四人测试。核对新局满血、旧Buff／冷却／球／物理历史清理，旧手动测试返回保持中止语义。
