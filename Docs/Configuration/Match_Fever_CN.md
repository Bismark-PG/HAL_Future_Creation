# Fever Mode · 正式比赛的终盘节奏

正式比赛中，服务器在以下两个条件中任意一个先成立时开启 Fever。

- 剩余时间 ≤ 90 秒。
- 开局至少有三名车手，本次淘汰／弃赛结算后恰好剩两名。

双人开局由时间触发。两个条件同时成立只播一次，之后持续到本局结束。同一批淘汰已经产生胜者或比赛时间已经归零时，直接进入结算。新一局从常速开始。

## 策划调参

开发和展演房间都引用 **Content → Data → Gameflow → DA_MatchFever**。三个倍率各自取值，把某项设为 `1.0` 即可单独比较另外两项。正式图当前配置如下。

| DA 参数 | 首测值 | 在 MVPB_Match 中的效果 |
| --- | ---: | --- |
| Gimmick Wait Multiplier | 0.75 | 四只弹簧拳的冷却由 0.50 秒变为 0.375 秒，出拳前仍有 0.30 秒预告。随机机关柱的滚动由 0.80 秒变为 0.60 秒，回升由 0.50 秒变为 0.375 秒。 |
| Special Ball Interval Multiplier | 0.75 | 两个生成盘共用一个时钟。通常每 25 秒投一颗，Fever 中为 18.75 秒，含完整的 1.50 秒亮灯预告。若首颗尚在等待，首轮也按剩余进度折算。 |
| Natural Energy Rate Multiplier | 1.25 | 各车型每秒自然回能增加 25%。例如原本 40 秒蓄满的车，在全程 Fever 下用 32 秒蓄满。道具的即时能量和技能消耗仍按各自 DA 结算。 |

`Remaining Seconds` 控制时间触发线，`Banner Seconds` 控制入场提示，默认分别为 90 秒和 1 秒。车手与观战者都能看到计时器下方的金色 **FEVER**，并听到一次观众欢呼。随后计时器右侧保留小标记。音效可替换 `Crowd Cheer`。

切入时，正在等待的机关按剩余进度换算，各只拳延续自己的相位。正在运动的拳完成本次伸缩。机关柱延续滚动位置或当前回升高度，有活动模型的柱子在升完后恢复阻挡。特殊球生成盘已经亮灯时，保持原盘位、球型和交付时刻，占位检查继续有效。黑洞、打滑区、电球和固定电幕沿用各自的生效、伤害和接触规则。场上已有球继续走球型 DA 的生命周期。

## 快速试玩

从练习房点 **Start** 进入正式比赛，然后在开发版主机控制台输入命令。

| 命令 | 用途 |
| --- | --- |
| `hal.Fever on` | 立即试听欢呼、查看 HUD 并试驾加速后的场地。 |
| `hal.Fever off` | 本局暂用常速，便于在相同场景做对照。 |
| `hal.Fever auto` | 恢复自动触发。处于常速且已经越过触发线时会立即进入 Fever。 |
| `hal.Fever status` | 主机或客户端查看本地收到的状态、服务器起始时间和三项当前倍率。 |

调试覆盖仅持续本局。正式比赛的自动触发、伤害和胜负均由服务器判定。

## 新机关如何接入

只给有“下一次何时启动”这一等待阶段的机关接入。机关在权威端开始运行时读取 `UHALRoomComponent::GetActiveFever()` 并订阅 `OnFeverChanged`，结束时解除订阅。以自身 DA 的基础时长计算下一次等待，切换时保留当前等待的剩余比例。向客户端复制阶段和服务器时间，由原有表现代码播放。预警、攻击动作、伤害及碰撞窗口由机关自己的规则定义。

新增球型只要进入共享生成盘的球池，即可使用相同的出球节奏。车型沿用现有 ASC 自然回能路径即可使用回能倍率。
