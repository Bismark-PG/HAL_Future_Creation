## 2. 建议保持的组合规则

| 同时发生的情况 | 建议固定的行为 |
|---|---|
| 驾驶倾斜＋发射 | 沿用A：发射峰值让驾驶Pitch贡献减弱，结束后恢复驾驶状态；不重置驾驶滤波 |
| 驾驶／发射＋受击 | 沿用B：受击在对应轴的峰值优先，另一轴仍保留有效贡献；淡出后恢复驾驶／发射当前进度，不重播被压低的旧动作 |
| 短时间多个有效命中 | 分别推进有限包络，按方向分量合成并统一限幅；相反方向可相互抵消，不因此改变实际命中次数或战斗结果 |
| 发射与受击先后／同帧交错 | 两类身份分开管理，确认或拒绝只作用于对应发射，不清除无关受击事件 |
| 受击＋轮转／转向／悬挂 | 保持各通道既有骨骼和空间；不重复应用Chassis Rotation，不从动画轮心反向驱动权威碰撞 |
| 同档＋Short／Long | 水平推送不同，受击骨骼幅度仍由同一有效档位决定；不把远推自动放大为更重档 |
| 降档／免疫／0伤害／伤害免疫 | 沿用服务器有效冲击结果及支撑过滤，保持伤害和冲击独立，不从HP变化补触发表现 |

最终模型Pitch／Roll仍受车型DA的Total Pitch／Roll Limit Degrees约束。车辆真实物理根可被正常击飞或翻转，骨骼附加偏移的限幅不限制真实物理姿态。首轮不新增Yaw／位移／落地回弹、改档位数或重新标定既有保存参数。

## 3. 联机与事件契约

- 发射保持拥有者即时预播＋可靠结果确认／拒绝；服务器接受的装饰通知供观察者消费，确认不重新计时。
- 受击保持服务器结果驱动，不增加受击预测。所有端使用相同方向／档位／包络规则，客户端不宣告命中或重算免疫。
- 沿用现有不可靠Multicast用于装饰，允许漏一次视觉；不补播晚加入的历史动作，不用装饰事件传递HP／击飞／脱球。可靠性不在本步扩大为“每次特效必达”。
- 核查重复、乱序、迟到、已结束预播的确认、序号回绕、短时间多事件，以及源Actor销毁后的独立事件数据；有界缓存与去重水位按目标实例生效。
- 物理重模拟不会创建新的装饰身份；网络校正也不以速度尖峰补造受击事件。
- 各端按照服务器游戏时间处理事件年龄；本地预播、远端PI及网络延迟可让显示时刻不同，不承诺同一墙钟帧骨骼角度完全相同。

## 4. 生命周期核查规则

| 边界 | 检查目标 |
|---|---|
| 普通小幅网络校正 | 沿用现有滤波／异常加速度抑制，不造新受击、不无故重新起播 |
| 真正瞬移／采样长帧／非法物理样本 | 清活动表现与采样历史，恢复时从新有效样本开始；保留必要去重水位，迟到旧消息不能复活旧动作 |
| Controller变化／重新配置 | 同时清理发射和受击，旧绑定事件不能进入新绑定；驾驶／轮转／悬挂按原重种规则恢复 |
| 旧Pawn销毁／新Pawn或Avatar | 事件不跨实例迁移；旧AnimInstance引用不能继续污染新车，不新增正式换车／重连系统 |
| 自救执行／严重倾斜 | B按原规则永久淡出，正立后不重播旧受击；A继续按自身有限包络与既有许可，C不擅自新设发射禁用姿态 |
| 停止／禁用表现后重新配置 | 无旧活动包络、错误Mesh绑定或第二套可见模型；非法配置仍走原静态外观回退 |
| 离屏后重新可见 | 既有Tick继续时事件照游戏时间消退，回到画面不从头补播；若已有路径暂停计算，则恢复时处理已过期状态，不新增离屏调度框架 |
| 游戏暂停与后台长帧 | 区分游戏时钟停止和采样卡顿：前者沿游戏时间保留剩余段，后者遵守长帧重置。只验证已有时钟／暂停边界，不建设联机暂停功能 |

以上是拟验证的契约，不代表所有边界已存在专门测试。若行为与契约冲突，先用测试或真实日志定位，再做最小修复；不把“代码里有ResetPose”当作整个生命周期已验收。

## 5. 建议执行顺序

### C-1：代码侧审计与组合缺口测试

核对Configure／StopPresentation／ResetPose、AnimInstance取数、A／B身份与时间校验、对应轴合成和最终限幅；复用原测试夹具，补有必要且可观察的组合断言。已有单通道测试不逐项重复抄写。

优先覆盖“发射预播进行中收到受击，再收到发射确认／拒绝”“受击淡出时另一个有效事件到达”“A／B活动时重配／失去控制者”“同档Short／Long共用视觉幅度”。只在确认缺口后收敛重复清理／校验或补诊断，不预先承诺修改网络协议或引入新生命周期管理器。

### C-2：必要修复、构建与基本双端组合验证

若修改C++，完整构建Editor／Game并保留Unity兼容性检查；运行当前普通回归及新增组合测试，记录实际计数。复用真实NetTest双进程，覆盖主机本车、客户端本车及双方观察者；优先低延迟，必要时复用已有单向80ms注入作基础迟到检查，明确不等同实测RTT。

原生时间步检查可用30／60／120，但不冒充实际屏幕FPS／渲染检查。可用可控消息顺序夹具验证重复／乱序／丢失，不据此宣称真实网络扰动通过。内存中重配／换Pawn夹具只验证既有原生生命周期，不交付正式玩法换车按钮。

### C-3：团队画面检查与VP收尾留档

团队用实际保存车型DA／AnimBP在正常测试场地：先单Host查方向、轮转／悬挂及回正，再双端互换发射／受击／观察者。至少覆盖直行／转向／漂移时发射并受击，连续球／机关命中，Heavy＋Short／Long，免疫／降档、自救／恢复、暂停卡顿及重新进入游戏。

原VP-4B画面和水平预设距离初测在此补记录，不擅自写成已经完成。代理提供逐项Editor／控制台步骤；所有DA／Blueprint／地图调整由团队手工保存。必要时区分“逻辑计数通过、真实画面未测、手感待调”。

## 6. 通过标准与范围边界

1. 同一身份最多启动一次；成功确认不重播，拒绝或失效不会留下永久姿态；缺失装饰通知不会改变玩法状态。
2. A／B缓存有上限、输出有限且不超过当前车型总限幅；多个事件结束后，其发射／受击贡献在配置包络或淡出时限内回零。**仍在行驶时驾驶倾斜可以非零**，不能错误要求总Chassis Rotation始终回零。
3. 重配／控制者变化／销毁／恢复后没有旧引用、旧事件或双模型；不累积历史事件在恢复帧补播。
4. 表现更新不额外改变根变换、速度／角速度、质量／碰撞、HP或脱球结果；Short／Long只保持原水平规则效果。
5. 编译、自动化、双端消息／快照、团队实际画面分别记录；未运行／失败／待测有明确状态与证据。

VP-4C完成意味着现有车辆表现链路的组合与生命周期收尾。F4的全玩法10分钟、约100ms实测RTT／1%丢包／20ms抖动、压力档和四台有线PC仍留MVP-B末尾；本步不接管该验收。四点物理悬挂／自然落地辅助、轮胎打滑FX运行时接入、相机震动和比赛框架也不纳入。
