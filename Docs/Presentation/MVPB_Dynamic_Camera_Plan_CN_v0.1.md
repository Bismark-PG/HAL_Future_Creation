# 动态相机0.1：取景、手动观察与调参方案留档

日期：2026-10-28（Asia/Tokyo）；基点`main/36ed9b4`。**用户随后确认FOV／基础距离也进入共用DA，并授权施工，Editor关闭确认已收到；现已完成0.1代码、完整两Target构建、93项普通回归和真实D3D12双端基本验证，等待团队手工接线／真人调参。** 实际配置和证据以[实施文档](MVPB_Dynamic_Camera_Implementation_CN_v0.1.md)为准。下文第1～9节保留此前讨论时的方案及“尚未施工”等时点表述，不再作为当前开发状态。示意数值不冻结为正式平衡，不把原生验证扩写成实际驾驶／斜坡／手感验收。

## 1. 用户目标与已确认输入偏好

- 先根据本车、其他玩家车辆和唯一主球的位置与权重计算合理聚焦点／相机距离。
- 本车允许偏离画面中心，但须限制在中心附近的一定范围。
- 玩家用右摇杆或鼠标移动有限拖动镜头，看到更远处；到达自车允许范围后限制继续向外拖动。
- 参数调试便捷度是首版要求，不能把可视化、参数分组和运行时调参全部推迟至以后。
- **鼠标已选择：相对移动累积偏移，停止输入后延时回中。** 未要求把鼠标屏幕绝对位置当作观察目标。

固定镜头姿态／FOV、软目标优先级、屏幕软／硬框、摇杆速度积分、共用Camera DA与实时调试的总体路线获本轮原则认可。具体权重、框大小、距离、速度、时长和主球引用的技术入口在施工规格与实测调参中细化，无需把每个数值列为前置审批。本轮不增加镜头组件、IA、DA反射字段或修改保存资产。

## 2. 当前工程基线

`FVehicleCameraConfig`和`UVehicleLocalConfig`位于`VehicleDefinition.h`；现有Local Config集中静态Boom Transform／Target Arm Length／FOV／Spring Arm Lag。Pawn组装SpringArm与Camera，应用一次保存配置，没有动态目标加权或观察输入。

现有GameState只有WaitingForPlayers／Playing，没有主球引用。`ABasicBallActor`已有Free／Controlled／Launched及复制状态，但当前没有“主球”的专用身份；调试补球可能增加其他球，不能以Actor遍历顺序暗中选择相机主球。

每名玩家保留独立本地相机。相机只读取本地可见的车辆／球状态，不向服务器发送镜头目标，也不让观察输入影响驾驶、车头瞄准或发射方向。

## 3. 建议的0.1边界

首版保持固定朝向、俯角与FOV，动态改变聚焦位置与相机距离，保留原静态镜头作A/B及关闭回退。先不扩展自动旋转、受击震屏、复杂遮挡避让、观战或多球选择。

主要在场地平面求聚焦点；斜坡／腾空的高度跟随另行平滑和限幅，不随车辆翻滚改变镜头Pitch／Roll。极端高度下优先保证本车可见，允许其他软目标离开画面。

## 4. 自动取景：聚焦点与距离分开处理

### 4.1 候选与权重

建议本车始终为强锚点，主球为较高优先级软目标，附近其他玩家为较低权重软目标。准确数值在DA配置，本文不冻结。本车最低权重与屏幕约束始终保留。

其他玩家及主球可分别配置影响距离、随距离变化的权重曲线和最大贡献。候选远离时逐渐降权，进入／退出影响范围使用平滑或滞回，避免刚越过距离阈值就跳镜头。主球很远或某玩家独自在场地另一端时，不要求将所有对象同时完整放进画面。

加权中心用于得到基础聚焦点：`C = sum(w_i * P_i) / sum(w_i)`。但加权中心不能保证本车在画面中心范围内，因此随后仍必须执行屏幕约束。

主球需显式、稳定地指定；无有效主球、尚未复制到本地或被销毁时，退化为本车与当前有效玩家。首版只消费一个引用，不为相机新建多球管理框架，也不由DA直接引用另一个World的关卡Actor。

### 4.2 距离与可读性

距离按候选目标在固定镜头姿态下的投影占用、各自软取景要求和有效权重求得，并限制在最小／最大距离之间。须使用当前实际游戏视口及宽高比，包含固定宽高比产生的有效画面；不能只用世界XY最大距离作为最终取景判断。

目标对距离的影响同样受权重／范围限制。权重很低的远目标不能仅因为参与了包围范围计算，就把镜头拉至最大。达到最大距离时，自车安全与车辆可读性优先，其他软目标可以不在镜头内。

建议拉远响应较快、拉近较慢，并对小幅目标变化设置死区，降低持续呼吸式缩放。主球状态改变引起的额外权重调整可以预留，但不要求0.1一次实现复杂状态策略。

## 5. 自车的屏幕范围与约束顺序

用归一化有效画面定义两个可视化框：

- **软框**：自动镜头尽量让自车留在其中，接近边缘时逐渐修正聚焦点。
- **硬框**：所有自动／手动／平滑结果都不得把自车继续推出此框。

示意起点可为中央40%软框／中央60%硬框；此处均指框占完整有效画面的宽高，分别是X/Y约0.3～0.7和0.2～0.8，**不是已接受参数**。X／Y范围及车辆留白可分别调节，确保调试界面显示实际含义。

建议流程：采集本地显示位置→候选权重／自动聚焦及距离目标→手动观察偏移→自车约束→位置与距离平滑→**基于最终实际镜头再次投影校验硬框**。平滑过程和高速运动也受硬框保护；单纯钳制目标点不能保证当前画面始终合格。

本车安全约束优先于手动偏移和其他目标完整入镜。具体约束修正须反馈到实际偏移，避免内部累计超出允许范围；回拖时应立即响应，不先等待消耗隐藏的越界输入。

## 6. 手动观察：已选鼠标方式与摇杆建议

鼠标相对Delta累积为观察偏移；有意义的输入结束后等待可调延时，再平滑回到当前自动聚焦结果。鼠标Delta按位移处理，不能额外按渲染帧率累乘；需有灵敏度与小噪声过滤。

右摇杆按推杆量控制观察移动速度，再按时间积分偏移；松杆后沿同一延时／回中规则处理。摇杆死区、响应曲线、最大观察速度和鼠标灵敏度分别调节，不能将两种输入原始数值直接相加。此路线随本轮总体方案获原则认可，具体手感参数不冻结。

建议内部保存归一化画面观察偏移，再结合当前镜头姿态与距离转换为场地平面偏移。缩放改变时仍维持可理解的屏幕拖动手感；最大偏移还受本车硬框与额外观察上限共同约束。到达边界后只丢弃继续向外的分量，沿边与反向拖动仍应立即有效，自动跟随也继续工作。

手动观察期间自动基础聚焦继续跟随比赛，但不能为了容纳拖动方向上的所有目标无限拉远镜头；首版建议手动输入只改变聚焦偏移，不单独要求扩大取景距离。玩家车辆继续移动、镜头缩放或当前目标改变时重新计算可达偏移。

切输入设备时使用有意义输入的阈值，避免摇杆噪声阻止鼠标回中。菜单／UI占用输入、窗口失焦、失去Pawn或重新Possess时，停止观察输入并按明确规则重种／清理旧偏移，避免回到游戏时突然继续拖动。桌面输入需配合游戏内鼠标捕获，不能一边操作菜单一边累积镜头偏移。

## 7. 参数与调试便利度

建议单独的共用Camera DA管理镜头参数，Local Config引用；相机不归车型Presentation DA。各车可以引用同一Camera DA，后续有实际需求再加车型例外。

现有静态镜头参数已经在Local Config生效。若迁到Camera DA，须先保存并迁移当前实际基线，明确唯一来源与静态回退，避免旧Local.Camera与新DA保存两套同时生效的同名规则。具体字段布局在施工规格中确定，不在本轮改资产。

| 配置分组 | 应集中暴露的内容 |
|---|---|
| 目标 | 本车／主球／其他玩家权重，影响距离、距离降权曲线及贡献上限 |
| 取景 | 最小／最大距离，目标画面留白，X/Y软框与硬框，固定镜头姿态和FOV |
| 观察 | 鼠标灵敏度，摇杆死区／响应曲线／速度，偏移上限，回中延时和响应 |
| 响应 | 聚焦响应，拉远／拉近独立响应，死区，目标变动过渡，高度跟随范围 |
| 调试 | 静态／动态A/B，重置观察状态，屏幕框、焦点与目标贡献显示 |

首轮就应支持PIE实时调权重、范围、距离、响应和观察手感，避免每次退出游戏。需要重种状态或重建候选的变化提供显式刷新／重置，不隐藏保留旧积分；不承诺所有资产结构变化都能无缝热改。

屏幕调试至少显示：本车软／硬框及实际投影点、自动聚焦点／手动偏移后的点／实际点、目标与实际距离、各目标有效权重、当前输入设备、回中等待／返回状态、限制原因。设计师应能区分“权重导致看向那里”“平滑尚未到位”“硬框阻止继续拖动”。

动态平滑与现有Spring Arm Lag统一设计，避免两套滞后叠加。相机消费客户端当前显示／预测的运动结果，并处理网络校正／真正瞬移的差别，不把每次速度或位置尖峰转换成镜头甩动。具体读取点在实现前按工程接口核查。

## 8. 建议分步验证与讨论出口

1. 先固定目标优先级、主球指定方式、自车屏幕约束和输入语义，保存静态镜头基线。
2. 自动聚焦／距离与Camera DA、实时调参、Debug框同步实现；用聚集／分散／球远离／窗口比例测试。
3. 加手动观察、延时回中、边界抗累计、移动／缩放过程中重新约束，验证鼠标与摇杆／菜单切换。
4. 检查高速、斜坡、腾空、翻车、自救、主球缺失／销毁、网络校正、主机与客户端各自独立画面，再调首轮参数。

当前总体路线已获原则认可，鼠标相对拖动＋延时回中为明确选择，尚无必须另开一轮确认的玩法阻塞项。示意数值作为初测候选，实际基线、数据迁移与技术入口在施工规格中落实。未新增C++、输入资产或相机DA，没有构建／自动化／UE运行，本次只讨论和留档。

## 9. 首版边界的建议默认处理

- 沿用当前实际保存的静态镜头作为基础姿态／FOV与距离基线，先保存再迁移，不把原生默认1200cm当作团队当前值。
- 手动观察松开／停止后采用可调延时与平滑回中；鼠标和摇杆的方向、灵敏度、死区及响应曲线均为配置项，具体数值由初测细化。
- 建议被击飞、眩晕、翻车和长按自救期间仍允许本地观察；镜头观察与驾驶许可分开，角色失控仍保留查看场面的能力。菜单／UI接管、失焦或失去当前Pawn时暂停观察输入并清理／重种旧偏移。
- 主球通过窄的显式身份／引用入口指定；暂不可用时平滑退回剩余有效目标，不用遍历顺序选另一颗调试球。该技术入口不要求用户指定C++类名或承担实现选择。
- 在最大缩放或观察范围处，保持此前确定的自车屏幕约束优先级，允许远处软目标离屏；参数都能热调，极端状态的安全退化由实现负责。

本节补充的是建议默认边界，不增加新的大块功能或把每个工程细节改为必须人工批准。尚未收到“开始相机施工”的指令，当前下一步仍为落实具体施工规格与保存基线。
