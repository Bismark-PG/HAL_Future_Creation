# MVP-B VP-4B：有效冲击车身回弹方案（v0.1）

日期：2026-10-23（Asia/Tokyo）。当前核对基点`main/0efa4100962b258a41b2bfa7c254f812deed7a21`，开工工作区干净，本机UE5.8.2-56702186、887份资产。用户反馈VP-4A“暂时表现没有问题”，本步仅介绍方案并留档，**以下为建议草案，尚未获施工授权、尚无VP-4B代码或新构建／运行测试**。

## 1. 目的与边界

在车辆受到有效规则冲击时，让车身沿受力方向短促倾斜并回正，使玩家更容易读出受击方向、轻／中／重档位及降档效果。VP-4A表现自身发射，VP-4B表现车辆接收冲击，二者共用现有C++表现组件、车型DA、帧快照与AnimInstance输出。

只改变Chassis骨骼附加Pitch／Roll；不改变碰撞根、真实速度／角速度、击飞、HP、脱球、控球点或发射方向。普通Chaos自然推挤继续存在。冲击免疫时不播放规则受击回弹，物理车仍可能被自然推动；单纯扣血或伤害免疫不决定本通道资格。

本步不包含落地回弹、垂直车身压缩、持续微振动、摄像机震动、受伤闪烁或新机关／技能，不重构物理冲击强度、驾驶或GAS。

## 2. 当前源码核对与入口选择

已核对`CombatResolver.cpp`、`HALImpactReceiverComponent.cpp/.h`、`HALCombatTypes.h`、`HALImpactTypes.h`及VP-4A合成／通知。球、炸弹、弹簧拳与普通接触已走统一结算／Receiver；机关后续只需按既有接口提交命中与档位，不分别调用动画。

需要解决的两个现状：

1. `LastImpact`是可合并的复制摘要，记录有效档位时物理检查可能尚未结束，没有完整方向／事件时间／支撑抑制结果，不能轮询或给它加RepNotify就当作逐次受击事件。
2. `bImpactApplied`目前表示响应已被接受／排队；普通支撑被抑制追加时仍可能为true且保留Medium档位。因此只检查Applied或档位会让贴地接触误播放。

建议在原生统一冲击处理成功收尾处发布窄表现通知，使用已解析的受力方向、实际有效档位及完整结果。以`bHitAccepted && bImpactApplied && ImpactOutcome==Applied && EffectiveTier!=None && !bSupportSupplementSuppressed`等结果门控，再检查方向、身份和时间；无效／拒绝请求不发布。它表达服务器已接受的冲击规则，不宣称Chaos已完成某个指定物理帧的积分。

**不能只以RuleDeltaVelocity非零为条件**：自然碰撞已经达到目标响应时，额外补足可能为0，仍可有真实有效的碰撞事件；在通过已有接触强度门槛及支撑过滤后按有效档位演出。不从HP变化、客户端Hit回调或未经处理的速度尖峰推断冲击。

## 3. 表现规则建议

| 结算情况 | 本通道建议行为 |
|---|---|
| Light／Medium／Heavy | 按最终有效档位选择一组车身幅度与时长 |
| Heavy降为Light | 使用Light表现 |
| 冲击免疫或降至None | 不播放规则冲击回弹；保留自然物理运动 |
| 0伤害＋Heavy，或伤害免疫＋有效Heavy | 正常播放Heavy回弹 |
| 高伤害＋None | 本通道不播放；以后受伤表现另接伤害结果 |
| 静止普通地面支撑追加被抑制 | 不播放，即使诊断档位仍为Medium |
| 同一对物体持续顶撞 | 沿用现有接触事件抑制，不按每次物理回调重复注入 |
| 分离后再撞或多个不同有效命中 | 作为独立事件；有限叠加并统一限幅 |

方向以服务器本次已解析的受力方向为准，在受击时转换为车辆局部方向并随事件发送，不在客户端用“当前球位置”重算，避免球反弹／销毁或车辆转向后演反。前后受力映射Pitch，左右受力映射Roll，斜向按分量混合，复用车型已校准的轴／符号。近乎纯竖直且无可读水平分量时不随意生成左右方向；本轮不增加垂直压缩通道。

车型表现DA建议增加独立`Impact Rebound`组，默认关闭。玩法来源继续只填写档位，**档位→视觉幅度／时间由车型表现DA集中映射**，不要求每颗球／每个技能重复填写角度。

以下仅为首轮调试起点，不是保存资产值或已确认最终演出：

| 有效档位 | 正面／侧面最大倾斜起点 | Rise | Return |
|---|---|---|---|
| Light | 3° | 0.04秒 | 0.18秒 |
| Medium | 6° | 0.04秒 | 0.25秒 |
| Heavy | 10° | 0.04秒 | 0.32秒 |

可分别配置Pitch／Roll幅度及方向符号。沿用有限时长解析包络，随后回零，复用现有最终`Chassis Rotation`输出；不新增第二套骨骼驱动。与驾驶倾斜及发射回弹合成后统一限幅，不累积角度或更改真实根姿态。施工时检查反向驾驶倾斜对受击可读性的抵消，不能靠无限增大角度处理。

普通腾空可保留短促包络；严重侧翻／倒扣及自救执行时建议将附加受击姿态淡出，避免遮盖真实物理翻转，伤害／冲击规则继续正常结算。具体门控在施工规格中固定。

## 4. 联机与生命周期建议

- **首轮不做受击预测**：只有服务器知道当次免疫／降档和最终资格。主机、拥有者客户端及其他观察者均消费服务器同一结果，客户端不自行宣布命中。
- 事件携带目标实例内递增序号、服务器游戏时间、有效档位、局部受力方向；攻击ID／Pulse可留在日志用于追踪。不同来源共用入口，不依赖来源Actor仍存活。
- 建议沿VP-4A装饰性不可靠Multicast通知当前相关端；服务器本地也走同一消费函数。允许丢包时漏一次装饰，不把它作为HP／击飞／脱球交付渠道，不补播晚加入的历史动作。若未来要求每次装饰必达，应独立评估通知可靠性，不能默认为已保证。
- 按服务器事件年龄重建包络阶段，去重、限制旧事件、短时间多事件和缓存上限；物理重模拟不重播装饰。各端渲染时刻可因网络延迟／PI而不同，不承诺同一墙钟帧显示相同姿态。
- 换Pawn、重配、长帧／瞬移、结束和恢复可见时清理／拒绝旧动作。A／B各自必要去重及基本双端检查在本步完成，VP-4C负责组合收尾，不把正确性全部推迟到C。

## 5. 建议施工顺序与验收

1. 先固定“何时算可演出的有效冲击”与方向／事件身份，补受击专用DA参数及有限包络。
2. 在统一冲击收尾接原生事件；接本地表现与观察者通知，复用现有Chassis Rotation并加入合成限幅。
3. 自动化检查四档、降档／免疫、0伤害、支撑／自然补足0、重复接触、多来源短时事件、过期／去重及生命周期；证明表现不改变刚体／HP／脱球结果。
4. 完整编译受影响Target并做必要双端测试，覆盖双方受击和观察者。提供手工启用步骤；代理不改Blueprint／DA／地图资产。
5. 团队单Host可检查撞墙／机关；双端检查车撞车、球、炸弹与弹簧拳、免疫／降档以及与发射／驾驶／悬挂叠加。完整扰动及四台有线PC继续按F4统一验收。
