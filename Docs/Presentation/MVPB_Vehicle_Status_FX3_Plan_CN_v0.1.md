## 1. 目的与分工

FX-3为每辆车建立本地的状态表现运行组件：记住当前哪些视觉效果应存在、由哪些输入维持、使用什么时间阶段，以及何时重绑或释放本车资源。组件由C++车辆基类组装，普通车型不逐BP添加逻辑。

| 环节 | 职责 |
|---|---|
| FX-1 已有 | 本车实际显示的Mesh、中心／尺寸和坐标入口 |
| FX-2 已有 | 共用定义、精确Tag目录、默认／例外查询和资源准备 |
| FX-3 本方案 | 状态实例、来源聚合、本车资源所有权、时间和生命周期 |
| FX-4 后续 | Overlay唯一所有者、优先级／有限融合／原材质恢复及真实粒子适配 |
| FX-5 后续 | 保存实际已调电击基线并迁移，保留本机／观察者提前表现、权威接续和焦痕 |

运行组件持有本车实例和资源引用，共享DA保持只读。表面最终可能由协调器为每个Mesh输出一个合成MID，不要求每个Tag各自覆盖一次Overlay；粒子按效果／层管理。FX-3先建立资源生命周期和渲染请求接口，FX-4落实绘制方式，避免先写一个临时直设Overlay的路径再推倒。

## 2. 已确认的最小运行合同

1. **实例身份为“本车＋视觉Tag”**。同一Tag默认一个持续实例，不按命中次数、GE数或通知次数重复生成。
2. **输入按稳定来源令牌更新／撤销**。同一来源重复提交是更新；A、B两来源维持同一效果，撤销A不能关闭仍由B维持的表现。令牌带本车绑定代次，旧ASC／旧Avatar的延迟退出不能关闭新实例。
3. ASC观察器提供“该视觉状态当前存在”的输入，不尝试从客户端Tag通知还原服务器全部GE身份和叠层。首次绑定须读取已有状态，不只等未来通知。刷新持续GE不一定产生Tag进入／退出，不能拿Tag回调直接当作每次命中事件。
4. 本地预测／观察者提前反馈与权威状态可作为不同视觉来源，汇入同一实例。FX-3只预留合并／取消合同，电击特有的确认／否决／接续时序在FX-5迁移，不把现有1.5秒等待泛化为所有效果的规则。
5. 来源数量只维持存在，**默认不自动增加亮度、粒子份数或改变伤害**。未来叠层强度由明确输入及效果配置表达；视觉来源数不是GAS权威层数。
6. 反复更新仍在生效的状态默认保持当前播放和曲线时钟，不重新执行整段起手。需要“每次命中闪一下”的效果通过明确瞬时反馈表达，不重启整个持续实例。
7. 最后来源退出后，按DA的FadeOut／Residue结束。退出／换车／销毁走强制清理，不带旧资源或尾迹进入新Pawn。
8. 淡出或残留期间再次收到来源，默认复用存活实例，从当前可见强度回到活跃，保持该实例的曲线时钟；实例完全释放后再进入才建立新时钟。实际各材质／粒子通道的过渡由FX-4落实，不提前承诺所有通道无跳变。

第1／5／6／8项按本次确认的默认规则接续：同Tag一份持续实例、多源只维持存在、刷新不重启、淡出重入复用。单个效果以后确有重播或特殊层数需求时，再以明确配置／输入扩展，不将所有状态写死为一种特殊电击行为。

## 3. 等待、重绑与时间

建议区分：无实例、等待资源／Mesh、活跃、淡出、视觉残留。活跃阶段包含淡入包络；物理与GAS不等这些状态。

- 状态先到、目录后Ready或外观暂时无效：保存当前需求，在资源／目标可用后补入持续段；等待期间来源已结束则撤销，不补播已过期的命中闪白／尾迹。
- Mesh变更：释放旧目标资源并绑定新外观，保留有效状态及实例时钟；每帧位置变化不是重建MID／粒子的理由。
- 换ASC／Avatar：解除旧监听、作废旧代次，重新采集新绑定的当前状态；旧引用与回调不可延续到新车。
- 时间曲线、淡入／淡出按共享规则执行。各端按本地可见状态建立实例，**不据此承诺Host／Client起始帧一致**。Tag存在本身不包含准确命中时间；必须精确同步的闪光／阶段由后续驱动提供事件时间或标记，电击迁移时核对现有时序。
- 输入／资源／目标变更用事件处理；仅动态曲线／过渡／空间更新需要时启用表现更新，空闲关闭。没有Blueprint Tick、逐帧RPC或GAS物理移动。

## 4. 已确认的三步施工顺序

| 小环节 | 交付 | 验证重点 |
|---|---|---|
| FX-3A：实例与来源 | 运行数据模型、稳定来源令牌、进入／更新／退出和阶段推进 | 重复输入、多来源任意撤销顺序、刷新、淡出重入、零时长边界 |
| FX-3B：本车资源与生命周期 | 接FX-1／FX-2，准备本车资源和渲染请求，处理等待／重绑／退出 | 两车独立、DA不变、旧Mesh失效、资源迟到、退场／跨图清理 |
| FX-3C：观察入口和诊断 | ASC状态观察合同、可控调试来源、状态／来源／资源计数与双端集成 | 初始已有效状态、绑定重复／替换、旧回调无效、未配置不阻断原流程 |

每步单独编译、自动化和留档；先做A，再做B、C。测试不能只断言容器数量，还应核对行为、资源归属和实际清理。

**FX-3采用旁路观察／受控调试验证，不让新旧系统同时接管当前电击。** 当前电击由原组件继续负责，通用路径正式接管安排在FX-5。FX-3结束可检查逻辑状态、实例和资源生命周期，不据此宣布材质融合／表面粒子或电击迁移已完成。
