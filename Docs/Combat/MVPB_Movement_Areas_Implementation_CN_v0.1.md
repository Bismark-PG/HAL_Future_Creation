## 1. 功能与数据流

一个可放置的原生 `HALMovementArea`，通过 `Settings.Kind` 区分 Slow／Slippery；范围由 `AreaBounds` Box 决定。自动进入／离开不需要 GA，区域自身没有 ASC。

```text
服务器 AreaBounds 与车辆物理根的 Overlap
 → 每辆车 MovementAreaReceiver 按区域来源登记
 → 加速度／速度上限／侧向抓地分别取最小区域倍率
 → ASC 上两类原生选中效果 GE
 → MovementEffectBridge 统一采样普通增量与区域目标
 → 权威物理帧动作＋版本2历史曲线
 → 同一 Movement 消费当帧有效倍率并施力
```

默认 Slow 加速度0.5／速度上限0.5，Slippery 侧向抓地0.2，恢复0.4游戏秒，均为方便观察的可调起点。不同车型继续使用自己的已调 Vehicle Definition／DA；区域不回写或重新应用基础配置。

## 2. 规则与长期接口

### 2.1 逐参数最强与其他 Buff

同为 Slow，A的速度限制更强、B的加速度限制更强时，分别取对应来源。Slippery 同样只取最小抓地倍率；不累乘区域，不对每个区域直接叠一个减益 GE。Slow 与 Slippery 可以共存。

普通运动 GE 继续使用 `AccelerationMultiplierDelta`、`SpeedLimitMultiplierDelta`，新增 `LateralGripMultiplierDelta`；区域接收器独占 `AreaAccelerationDelta`、`AreaSpeedDelta`、`AreaGripDelta`。后者是选中的区域贡献，不是其他技能的通用属性入口。

对每个参数、每个物理帧F：

```text
有效倍率(F) = Clamp(1 + 普通活动GE增量之和 + 区域倍率(F) - 1, 0, 3)
有效物理参数(F) = 车型DA基础值 × 有效倍率(F)
```

例如普通速度Buff增量+0.25、区域速度倍率0.5，最终为0.75倍；DA最高速度2000cm/s时为1500cm/s。先求和再钳制，保留饱和或负向 Buff 的原始贡献；离区只撤掉区域贡献，不重设普通属性。

原生 `HALSlowAreaEffect`／`HALSlipperyAreaEffect` 是接收器内部使用的无限期、Avatar作用域 GE，数值用保留的 SetByCaller Tag 传入。每个 Avatar 最多各一份选中效果，来源清单另行保存。无需手工创建对应 GE 资产或把它们加到 PlayerState.DefaultAbilities。

未来普通加速／减速／抓地 Buff 可继续用普通属性 GE，并由已有 GA 管许可、冷却和动作。未来主动技能生成区域可由服务器 GA 生成这个 Actor。原生机关可调用 `ConfigureArea`／`SetAreaEnabled`，不需要额外运动复制或修改每个玩家的 PlayerState 蓝图。新增完全不同的运动参数时，仍须扩展属性、桥接、物理消费和历史，不是只加一个 Tag 就自动产生物理效果。

### 2.2 恢复与重入

区域贡献变弱时，从该实际物理帧的区域值线性恢复至当前目标；全部离区时目标为区域1倍，普通 Buff 仍独立生效。更低且强于当前值的目标即时生效。恢复中重入从当前曲线值转向新目标，不创建多份离区任务。

强区退出但仍处弱区时，只向弱区恢复。每项恢复时长取原获胜来源与新获胜来源的较大值；等强来源的时长取最大值，避免遍历顺序决定结果。0允许显式关闭该过渡，范围0～10秒；默认0.4秒。

服务器按固定物理步把恢复秒数向上量化为帧数，在实际生效帧记录曲线起点／目标／起始帧／总帧数。每次参数变化仅发送一条可靠参数动作，不逐渲染帧重施 GE。动作携带上一次服务器已消费的曲线定义，客户端缺少前一条动作时也不能自行猜恢复起点；后续权威时间线保留完整定义用于回滚／窗口恢复。GT若尚未收到上一条的物理帧确认，先合并待变参数，下一次安全发布。同一GT帧多个来源／类型退出时逐参数合并恢复请求，后一次不相关的更新不能清掉前一次请求。

物理State另保存当帧实际消费的三倍率；身份／曲线一致但实际使用值不同也需要校正，不能只比较曲线目标。S(F)记录F-1的消费值，插值查询相应权威曲线计算F-1，不把两个端点的倍率线性平均。客户端自定义已用帧记录同样比较当前服务器帧映射下的实际倍率，避免漏掉过渡中帧偏移变化。

普通 Buff 开始／结束会改变普通增量，但不重启区域恢复。GAS 在游戏线程施加／清理效果；重模拟只读纯数据曲线，不重施 GE、不重复推进 GAS 时间。历史协议由1升级到2，联机双方必须重编同一代码版本；不能混用旧客户端二进制。

恢复的是参数，不是强制恢复线／角速度。打滑只缩放正常与手刹的侧向抓地速率、最大侧向抓地加速度；不改转向扭矩、质量、惯性、重心、碰撞体、物理材质或车轮表现规则。已有侧滑仍需真实施力收敛，0.4秒后不保证侧滑速度已归零。减速沿用原超速修正力，不直接设置速度。

### 2.3 生命周期与区域范围

只认车辆真实物理根组件；视觉车身、车轮或其他组件的重叠不产生额外来源。车辆在服务器运行时开启物理根的 Generate Overlap Events，兼容现有保存蓝图的旧默认，不修改碰撞Profile／刚体模拟。

区域是3D体积，不是接地材质：物理根进入Box即作用，Box过高时腾空车辆仍可能位于范围内。应按场景需要设置高度。抓地力仍沿用Movement的原接地执行条件，不额外吸住空中车辆。

重复进入／重复启用不叠加强度；初始已在区内和重新启用时扫描现有重叠。离开／禁用／销毁解除该来源。未绑定ASC时保留当前重叠登记，绑定后计算；旧Avatar解除绑定清除自己的GE，旧车的迟到清理不能删除新Avatar的效果。区域无Actor Tick，不定时扫描全场。

区域效果作为场景环境持续存在，不另外要求 Playing 才登记；Waiting时驾驶输入仍由原比赛规则限制。当前不实现区域伤害、冲击、道具拾取、区域生成时序、粒子或轮胎FX。区域GE的State Tag表达当前选中区域效果，离区后Tag可先消失，物理恢复曲线仍继续，不能以Tag消失推断倍率已到1。

## 3. Unreal Editor 配置步骤

### 3.1 更新原生模块

1. 保存要保留的工作，关闭 Unreal Editor 及游戏进程，关闭 Live Coding 路径。
2. 完整编译当前工程 Editor Target；团队已有双击编译工具可继续使用。拉取新代码的另一设备同样先编译，再开项目，避免用旧DLL加载新增组件／属性。
3. 打开现有 `MVPB_NetTest` 或已复制的功能测试地图。当前车辆、PlayerState、表现DA、Network Physics DA沿用已调配置，不需要修改 DefaultAbilities。

### 3.2 创建减速区域蓝图

1. Content Browser 在团队约定的机关目录（建议 `/Game/Blueprints/Arena/MovementAreas`）右键 → Blueprint Class → All Classes。
2. 搜索 `HALMovementArea`，选这个 C++ 类，创建 `BP_Area_Slow`。
3. 打开蓝图，选择 Class Defaults，在 Details 搜索 `Movement Area`。展开 `Settings`：

| 字段 | 初测建议 |
|---|---:|
| Kind | Slow |
| Acceleration Multiplier | 0.5 |
| Speed Limit Multiplier | 0.5 |
| Recovery Seconds | 0.4 |
| Enabled | 勾选 |

4. Components选择 `AreaBounds`，在Shape中设置Box Extent。单位cm，Extent是半尺寸，例如X=500、Y=500代表约10m×10m。Z可先设200，放到能覆盖车辆物理根高度的位置。
5. 保持碰撞为原生 QueryOnly／Overlap，不启用 Simulate Physics，不把区域Box改为阻挡车辆。
6. Compile、Save，拖入测试地图。

### 3.3 创建打滑区域蓝图

1. 同样继承 `HALMovementArea`，创建 `BP_Area_Slippery`。
2. Class Defaults → Settings，Kind选 `Slippery`，Lateral Grip Multiplier先设0.2，Recovery Seconds先设0.4，Enabled勾选。
3. 调整 `AreaBounds`，Compile、Save，放到与减速区分开的可驾驶区域。
4. 如需可见范围，可手动增加纯表现平面／材质／边框；组件碰撞设 NoCollision，不影响物理根检测。原生Box主要用于Editor范围配置，当前没有自动区域特效。
5. 保存测试地图。可用同一蓝图的不同关卡实例覆盖Settings，不必每种强度新建蓝图或GE。

### 3.4 重叠用测试布置

复制两份减速实例，在中间留出重叠带：A加速度0.7／速度0.3，B加速度0.4／速度0.8，恢复均0.4。单独A应是0.7／0.3，重叠应是0.4／0.3，单独B应是0.4／0.8。重叠带加一个抓地0.2的打滑区，验证减速与打滑共存。

这些是团队手动步骤；代码代理不生成或保存 `.uasset`／`.umap`，不会覆盖已调蓝图／DA。

## 4. 团队功能测试与调试

先用一名主机在测试场景验证，再按现有双进程 Listen Server 流程验证拥有客户端；从Entry进入或直接启动NetTest均沿用原流程，由主机 `HALStartMatch` 开始。

运行中开启 `hal.DebugHUD 1` 观察Movement的Accel／Speed／Grip倍率及Slow／Slippery状态；`AreaFade=1`表示区域参数正在恢复，原`Recover`／`Recovery`仍表示网络历史不足的恢复状态，两者不同。用 `HALGASStatus` 检查两端当前状态。`hal.MovementAreaLog 1`记录服务器来源数、选中倍率和恢复秒数；`hal.MovementEffectLog 1`记录实际物理帧、Revision、当前倍率／目标和恢复帧数。用0关闭日志。模拟代理不运行同一驾驶组件，其Movement未Ready不能当作拥有客户端失败；远端GE／属性与实际驾驶位置分别检查。

最小手测清单：

1. 直线通过减速区，感受加速／最高速度下降、离区短暂恢复；不能瞬间清零速度。
2. 转向或手刹侧滑通过打滑区，抓地明显下降，离开后逐步恢复；车辆仍能自然碰撞，不突然扶正。
3. A→重叠→B以及反向穿行，倍率按每项最强决定；从强区退出但仍在弱区时不得先跳到1。
4. 离区恢复中重新进入，确认立即转向当前新目标，没有多段旧恢复排队。
5. 使用现有 `HALMovementBoost` 调试加速，与区域共存；离区后若Buff未到期，应恢复到1.5加速度／1.25速度，Buff到期后再回1。
6. 两端分别驾驶、同时经过、带球／发射；检查不存在持续回拉、无法操控或其他车辆被误加效果。
7. 原生自动化覆盖启停／销毁／Avatar生命周期。团队后续制作机关开关时调用服务器 `Set Area Enabled`，不在Level Blueprint拆分核心状态。
