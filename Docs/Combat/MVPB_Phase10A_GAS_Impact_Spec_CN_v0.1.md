## 3. 长期数据契约

以下是职责与字段语义，具体 C++ 名称可在 10-B／10-C 采用项目现有命名风格确定；不为每种球、技能、机关分别造一套命中流程。

### 3.1 一次攻击的来源快照

`AttackSourceSnapshot` 在攻击实际成立时由服务器生成，记录：来源类别、稳定的玩家 ID（没有玩家时可空）、可选的当时 Pawn／PlayerState 引用、效果标签、发射／动作序号、攻击基础值、该动作倍率和有正有负的倍率增量总和。对飞行球，**发射时**锁定这些值，并与球的 Launched 生命周期关联；Pawn／PlayerState 此后销毁也不能让这次攻击失去已保存的来源和数值。将来技能可增加效果载荷，但球本身不因此获得 ASC。

玩家主动攻击的原始伤害为：

```text
RawDamage = CapturedVehicleAttack × max(0, ActionMultiplier + sum(MultiplierDeltas))
```

其中车辆基础攻击体现“谁来打”，动作倍率及增量体现“这一击有多狠”。增量可以正负叠加；缺省动作倍率应为 `1`，但迁移时须从当前已保存伤害校准，不能凭 C++ 默认值替换 DA。球飞行期间攻击 Buff 到期或发射者退出，不回算 `RawDamage`。场地机关使用**自身配置的基础伤害**，不借用某位车辆的基础攻击；即使有触发者归属，也不自动继承其倍率。

目标的防御、受伤倍率、免疫和当前有效状态在**命中时**由服务器判定。目标最终扣血可以是 0；这不等于命中无效。防御的具体算式、先后次序与允许的免疫范围尚未作为 10-A 的既成数值承诺，必须在 10-C 编码前写入规则和测试。

### 3.2 标准命中请求与结果

标准命中请求由服务器可信的碰撞／技能／机关事件生成，携带目标、来源快照、命中位置／法线、可选物理测量、伤害提案、独立冲击提案，以及来源 Actor 身份加服务器事件序号。客户端不能上报“命中谁”“伤害多少”“档位多少”。同一来源事件只消费一次；网络 RPC 重发和重复物理回调不得二次扣血、二次冲击或二次切换球状态。

结算结果分开记录 `HitAccepted`、最终伤害、来源档位、目标实际受冲击档位、施加的物理结果、脱球与消费状态。**不以 `HPChanged` 作为 `HitAccepted` 的代理。**因此 `0 伤害＋强冲击`、`高伤害＋无冲击`、目标 HP=0 后受击、免疫伤害但受冲击均有明确表达。正式淘汰状态将来单独决定是否还能被命中，不能把 HP=0 偷换成淘汰。

### 3.3 冲击档位与目标响应

冲击提案允许 `None / Light / Medium / Heavy`；前三档沿用当前 `EVehicleKnockbackTier` 的含义，`None` 表示这次没有额外的档位物理效果。来源可选择：

1. `PhysicalMeasurement`：按该来源的测量策略及阈值选档。球速／球冲量与车车碰撞冲量量纲和分布不同；**统一档位结果，不强迫共用同一组输入阈值**。
2. `ExplicitTier`：由合法的球属性、技能或机关直接指定档位，不要求物理速度达到某阈值。高伤害仍可配置低冲击或无冲击，反之亦然。

服务器先确定来源档位，再按目标当时的冲击免疫／抗性得到实际受冲击档位，最后应用统一的档位物理结果。**脱球是目标响应规则**：目标配置最低脱球档位；例如普通车可允许中档脱球，重车只在重档脱球。该最低档位的初值须对照旧 `DropCollisionImpulseThreshold` 的实测行为选取，10-A 不擅自指定或重调。普通车辆碰撞仍不直接造成 HP 伤害，但可以有碰撞物理推动及符合规则的脱球。现有三档水平／垂直速度与翻转结果先原样迁移，再用分方向、墙角和网络回归测试决定是否调整。

冲击档位是权威规则结果；Chaos 刚体继续负责碰撞与实际运动。GAS 可管理免疫／抗性／硬直状态，不能逐帧执行击飞或代替 Network Physics 重模拟。

## 4. GAS 所有权与配置边界

- 玩家 `PlayerState` 持有 ASC，并使用面向玩家的 Mixed Replication；当前 Vehicle Pawn 作为 Avatar，出生、Possess、退出和重生时正确初始化／清理。ASC 的 Owner 与 Avatar 生命周期不互相混淆。
- 玩家生命值、攻击基础值、需要在局中变化和复制的防御／抗性等放在职责明确的 AttributeSet。车辆质量、碰撞形状、悬挂、基础驾驶加速度和抓地仍在 Vehicle DA。不能仅因“是数字”就全部迁进 GAS。
- 被动测试车辆若继续作为可受击目标，走同一战斗目标契约，并由自身持有适合非玩家的 ASC／AttributeSet；不为它创造第二套受击公式。实现前核对测试地图是否仍使用该 Actor。
- 球、普通道具及场地机关默认不持有 ASC；它们可提供来源快照和伤害／冲击提案。GA 管动作许可和阶段，GE 管伤害结果及持续状态；物理运动仍在组件中执行。一个临时加速 GE 只改变有效运动倍率，Movement Component 才实际施力。
- 生效运动倍率必须在服务器与拥有客户端的相同物理帧可复现；改动后的参数需要进入网络物理历史或等效的帧化快照。只在服务器改 GAS Attribute、让客户端仍用旧参数预测，会造成回拉。10-F 专项验证，不把 GAS Prediction 误认为车辆物理预测。

## 6. 待后续环节明确的规则

1. **目标防御公式**：在 10-C 编码前确定减法防御、受伤倍率、免疫的先后顺序与钳制范围。10-A 固定的是“攻击方发射时锁定、目标方命中时判定”的时间边界。
2. **旧数值到新攻击公式**：当前普通球 `VehicleHitDamage` 是固定伤害；车辆基础攻击与球动作倍率的新资产字段须以当前保存的 25 HP 行为为校准目标，不能让迁移过程无意放大或缩小伤害。
3. **物理来源选档／脱球映射**：旧球速档位和旧脱球冲量阈值分属不同量尺。需要记录数次有代表性的车车碰撞与球命中样本，再确定普通车和重车的最低脱球档位；10-A 不伪造可自动换算的比例。
4. **多效果叠加／运动帧生效**：在 10-E／10-F 前分别固定持续效果叠加策略，以及 GAS 数值变化映射到 Network Physics 帧历史的具体机制。此处只约束结果可复现。
