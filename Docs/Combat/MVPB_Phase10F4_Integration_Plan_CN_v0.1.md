## 3. 第一轮需要补什么

1. **保存配置真实入口**：加载当前NetTest／PlayerState的授予配置，经原Primary技能请求激活`GA_MovementBoost`，核对其实际GE类。复用已有输入与GAS通道，不在测试中直接设置运动倍率来替代技能释放。
2. **真实组合与回滚**：对发射／后坐、受击／脱球、加速到期与外部速度、旧帧倍率消费等可确定部分补自动化／双进程用例。测试通过生产球状态、Combat和Physics路径取得结果；不能只调用容器方法或写速度后宣布联机组合通过。涉及混沌碰撞观感的项目保留团队实测。
3. **生命周期与原免疫回归**：复用现有作用域清理／HP及冷却测试，在加速与免疫交叠时补相互独立性检查；Playing阶段不新增重连／重生入口，只在测试夹具换Avatar，真人退出后另开局复测。
4. **必要读数**：当前`HALNetMetrics`只输出Pawn／Local／PhysicsFrame／ResimRuns，不能当RTT证明。实施时增加或接入窄的只读连接RTT与可用包统计采样，记录注入配置、采样窗口、FPS及物理稳定性；未知数据明确写不可用。抖动应记录模拟器语义及实际采样分布，不把帧差、回滚次数或两台机器日志时间差当RTT／jitter。
5. **可复核输出**：每轮独立日志／报告，关键事件用PlayerId、Epoch、Revision、物理帧、球StateSequence／LaunchSequence／命中事件标识关联；源码／资产基线与摘要进入Git，原始Saved报告只作本机证据。

保持测试代码窄且可选择运行；无生产需求时不建设通用机器人、跨机控制器或永久逐帧统计系统。诊断关闭时不持续刷Replay日志；性能采样和短时详细回滚抓取分开，以免日志量扭曲性能。

## 4. 玩法组合矩阵

每个功能组由主机和拥有者客户端分别作为发动者；另一端观察远端车。关键边界覆盖“开始时、持续中、刷新时、到期后”，避免仅测试无Buff稳态。

| ID／组合 | 执行重点 | 预期 |
|---|---|---|
| G1 空车驾驶 | 前进／倒车、转向、刹车、滑行、漂移；接近基础／加速上限时开始或到期 | 前进／倒车加速度及驾驶上限按当帧倍率；原转向参照／刹车／抓地规则保持；到期不硬清零速度 |
| G2 持球与发射 | 争球、持球加速／漂移、在开始／刷新／到期附近发射，两端互换 | Holder／Launcher／状态一致，发射仅一次；后坐仅一次，回滚不重施技能或重复脱球；攻击快照按服务器接受发射时保存 |
| G3 碰撞与脱球 | 低速／高速、正撞／侧撞、墙角、连续接触、持球受击；三档／降档子项补齐 | 同一次权威事件不重复伤害／动作／脱球，重新捕获锁有效；保留自然Chaos碰撞，不把车辆碰撞变成主要扣血来源 |
| G4 腾空与到期 | 上坡／碰撞腾空，在空中开始或到期，随后落地；受外部冲击后到期 | 不清除真实线／角速度，不在空中额外强制制动；按原悬挂／落地辅助工作，无永久恢复失败 |
| G5 加速＋冲击免疫 | 同车同时有两效果，分别先到期／移除；免疫前后球命中、目标持球 | 加速不授予伤害或冲击免疫；冲击免疫仍允许伤害，按既定有效档位决定脱球；各自到期只移除自身贡献，HP／其他冷却保持 |
| G6 输入与生命周期 | 按住／松开／再按、快速重复、Waiting拒绝；带加速客户端退出、主机退出；夹具换Avatar及旧回调 | 原按下边沿发动，松开再按可刷新且不叠强度；无旧Epoch污染、残留球约束或永久Boost；Owner退出清理，新局不继承旧Buff |

**数值解读**：加速不直接乘到伤害、冲击档位或后坐参数上。但实际车速增加可按原自然碰撞测量改变冲击选档，球发射也沿用既有车速参与规则；不能要求不同物理接触的冲击数值强行相同。固定输入上下文下，伤害／冲击仍相互解耦，0伤害可有冲击，冲击免疫不免伤。

### 4.1 只有一个技能键，如何覆盖免疫组合

正式加速主线继续使用已提交的一个Primary，不把免疫与加速同时授予同一个InputTag，也不新增第二按键。

自动化夹具可仅在运行时额外授予原免疫GA，通过测试持有的SpecHandle在服务器激活，验证真实8秒GE／20秒冷却与加速共存；测试结束撤销授予，保存的DefaultAbilities不改变。它验证共存与规则，不伪称新增了玩家可操作的第二槽位。

团队组合测试可用既有`HALImpactDebug`叠加／移除免疫状态，但该无限调试GE不能充当8／20秒技能验收。若补原免疫实际按键／冷却验证，则按独立测试轮次临时把Primary切回原免疫GA并完整重开局；这是配置步骤，由团队操作，结束后恢复已提交的加速配置。具体操作随F4-A交付，不在本方案阶段修改资产。

## 5. 网络与四机方式

低延迟先按0～20ms实测RTT、0%loss建立基准；目标与实际值分列。主验收重复G1～G6的关键路径：100ms RTT、1%loss、20msjitter；压力档150ms／3%／50ms另列，允许可见修正，不能有永久分叉／重复结算。不同场景无需无意义地遍历所有物理输入，但开始／到期、控球／发射／后坐、受击和退出必须覆盖。

实施前核对本机UE5.8.3的`NetEmulationHelper`／`NetConnection`支持的延迟、丢包和抖动语义，按收／发方向配置，避免双向叠加出错误工况。用连接采样确认实际RTT及分布；不把“设置50ms”直接写成“100ms RTT已通过”。先用独立游戏进程验证，再在双机／四机记录真实环境；不新增第三方网络插件。需要外部网络工具时另按团队环境选择，不在此承诺尚未可用的设备。

四机使用相同Development打包构建、UE补丁／提交／资产，同一有线交换机／路由器，每机一名玩家。从Entry正常Host／Join／Start，客户端填写主机LAN IPv4；127.0.0.1只用于同机。记录每台机FPS／Game／Draw／GPU、物理帧、带宽／包统计、实际RTT，主机和至少一台客户端保留视频及日志。每分钟保存一次轻量快照，详细Movement日志只在短窗口开启。

四人阶段先低延迟10分钟基础玩法及技能压力，再复用同一扰动档；包括多人争球、同时技能、车辆互撞、客户端持球／发射后／带Buff退出、主机退出及Playing拒绝新连接。现有比赛未含淘汰／观战／重连，不因此补建这些功能。

## 6. 通过标准与证据边界

沿用既有v0.2门槛，不凭未测数据新造位置／角度阈值覆盖DA：

- 100ms RTT下普通驾驶输入由预测立即响应；无碰撞驾驶不周期性明显瞬移。
- 硬碰撞可有修正，但连续明显振荡不超过1秒；发生时保留视频／时间戳，不能只看ResimRuns数量判断观感。
- 扰动停止后，球State／Holder／Launcher在`2×实测RTT+100ms`内收敛；这个门槛用于球状态，不能直接当运动Buff恢复时限。
- 每个LaunchSequence至多一次发射状态转换与权威后坐；每个命中事件至多一次伤害，脱球与规则动作不重复；1%～3%loss不能形成永久球权错误或重复发射／伤害。
- 运动倍率按对应权威帧／Revision离散消费，比较容差沿F1的1e-4；刷新数值相同不制造新边界。帧／Epoch／Revision精确比较，不能用最新中性值覆盖仍应加速的旧帧。
- GE自然到期仍用游戏世界时间；GT／PT采样、复制有正常边界延迟。超窗口可暂时Recovery，须在恢复可用检查点后回到Ready并最终1／1，无永久状态分叉；结合帧与历史覆盖记录恢复过程，不虚构固定恢复毫秒门槛。
- 双人至少10分钟无永久不同步或无法继续控球；四台有线PC完成基础争球／发射／碰撞／技能压力。无玩法相关新增Ensure／Assertion／Fatal或未解释的网络错误。

已知Entry不可聚焦Widget错误单独追踪；本步不因历史菜单问题扩展功能，但若实际阻塞Host／Join，记录并做必要最小修复后再验收。音频／EditorDataStorageUI启动提示与玩法错误分别列出，不写“零Warning”掩盖已知输出。

每个ID／网络档记录提交、构建／资产、操作者角色、操作步骤、预期／实测、日志／视频位置与结论，状态为通过／失败／未测。不能以之前45项或80ms单向smoke替代F4新结果；不能以F4-A完成标记整个F4／阶段10验收。新发现缺陷只修与本步相关的最小范围，并重跑受影响场景和必要回归；不为手感调优顺便改变已保存DA。
