## 2. 本阶段目标与边界

让一个持续运动GE改变现有车辆的有效参数，同时保持服务器、拥有者客户端预测／重模拟和远端表现收敛。首例优先持续加速；减速可以复用倍率桥接，低抓地在首例验证后按实际需要扩展。

```text
GAS的有效运动数值
  → 游戏线程生成纯数值快照
  → 按服务器物理帧同步／保存历史
  → ArcadeVehicleMovementComponent消费
  → Chaos施力与碰撞
```

基本计算方向：`有效运动参数 = 当前Vehicle DA基础值 × 当帧有效倍率`。无效果时倍率为1，保留现有手感；不把当前DA值抄成新的C++默认值，不改写共享DA，不反复调用初始化配置来清掉运行状态。

GAS管理效果施加、持续、叠层／刷新、移除与有效数值；Movement执行运动。普通Buff不突然修改质量、惯性、重心、碰撞尺寸，不用逐帧SetActorLocation／硬写速度实现加速。运动倍率不直接乘到伤害、冲击档位或后坐动作上；它对实际车速／位置的影响可以自然影响后续物理过程。

本阶段不建设完整道具库、技能栏、车型技能授予库、动态机关框架、死亡／观战／胜负流程或正式技能演出。弹簧拳接入和被命中者独立禁捕仍按既有决定后置。首例不要求新增完整区域Actor或主动GA，测试入口只负责请求／施加正式GE，不承载另一套运动规则。

## 5. 线程、权威与帧历史契约

1. **服务器来源**：运动倍率由服务器合法GE／Attribute结果决定。客户端可请求动作，不提交可直接采用的倍率、持续时间或任意生效帧；不能把客户端输入包携带的数值当成权威Buff参数。
2. **事件驱动与初始采样**：通过属性变化／效果生命周期及Avatar绑定事件更新游戏线程快照。初次绑定也要采样当时状态；避免每帧GA Tick或在物理线程读取ASC／UObject属性。取消订阅／销毁清理须完整。
3. **线程安全交接**：快照是纯值数据，语义上含当前Avatar身份、版本／序号、服务器物理生效帧及有效倍率。具体结构、锁／回调及序列化格式待规格和本机引擎源码验证，不在本文承诺尚未实现的API。
4. **按帧复现**：开始、刷新导致的有效数值变化、到期／驱散引起的恢复均进入同一权威时间线。若回滚到效果仍有效的旧帧，即使当前GE已结束，也必须使用旧帧倍率；重模拟不再次施加GE或推进一次新的效果生命周期。
5. **同步与恢复**：优先复用已有Network Physics状态／动作和历史机制，明确权威变化如何到达拥有客户端。仅复制“最新Attribute”不够；只向客户端发一次瞬时事件、丢失后永久不同步也不够。迟到、丢包、乱序、重复、历史窗口不足和Avatar更替的恢复方案须在10-F-1写清并实测。
6. **区分两个预测问题**：现有驾驶输入预测继续；首例建议由服务器确认运动效果，客户端按收到的权威帧校正。是否另加GAS技能预测须独立决定，不能因接了GA就默认物理参数正确或由客户端决定真实Buff。
7. **职责固定**：Movement消费通用有效参数，不识别`GE_某技能`名字／资产路径；Content配置改数值，不改物理算法。参数序号相同的重传应幂等，旧Avatar更新不能影响新车辆。

10-F-1必须选择并证明一条可行的帧同步／恢复路线后再编码。不得在未验证接口能力时把“以后接历史”作为临时绕过方案。

2026-10-17已据本机引擎源码与真实历史容器探针选择可靠Authority绝对参数动作＋带有界时间线的State检查点，固定PostSolve的F+1起点语义、迟到／缺锚点恢复与参数历史边界。详见[具体规格第3～5节](MVPB_Phase10F1_Spec_CN_v0.1.md)。容器验证不包含端到端传输或新参数的真实Solver重放，F2出口继续要求这些实际验证。

### 6.1 首例玩法规则（2026-10-17，用户已确认）

1. **作用范围**：加速度倍率同时作用于前进／倒车的驱动加速度，速度上限倍率同时作用于前进／倒车的驾驶速度上限。刹车减速度、滑行阻尼、抓地和转向参数保留基础配置；高速转向衰减继续以基础MaxForwardSpeed为参照，不把有效驾驶速度上限写回该基础字段。实际车速改变仍自然影响现有转向计算。
2. **不同GE合并与数值范围**：两类有效倍率分别按`clamp(1 + sum(各活动GE的倍率增量), 0, 3)`计算，例如+0.5与-0.3合并为1.2，不连乘。0～3为首轮可调测试保护范围，不是最终平衡值；0只限制主动驱动／驾驶上限，不冻结Chaos刚体、清零速度或免除冲击。最终有效值钳制，不破坏各GE原始贡献，移除后按剩余贡献重新计算；非有限值拒绝。叠加层数策略继续由各GE定义。
3. **多来源、到期与清理**：本次定时加速GE按目标聚合，同一目标无论来源重施均共用一层，成功重施从本次起再计5秒，不增加强度或累计时长；不同GE的贡献分别保留／移除。到期或合法驱散时仅恢复有效参数，保留真实线速度／角速度，接地时沿用现有阻尼／超速修正，腾空时不额外制动。首例为Avatar作用域，换车／失去Avatar清理，不带到新车，不重置HP或其他冷却；Owner退出沿用现有清理。未来区域重叠的按来源退出不能通过移除本次共享定时GE来误清其他来源，应届时使用独立贡献句柄。

用户已明确同意上述三组规则，不再重复确认。服务器确认效果、事件驱动采样、线程安全传递、历史帧重放和序号／Avatar隔离沿用既定架构约束；具体Solver生效帧、同帧更新顺序、迟到／窗口不足恢复路线、精度和日志属于10-F-1技术设计，应检查本机引擎后落档，不要求用户选择底层API。首例继续不新增主动GA／冷却或替换免疫Primary技能。
