# MVP-B 10-D：全来源冲击档位与抗性讨论（v0.1）

日期：2026-10-15（Asia/Tokyo）。本文件保留讨论时的建议与风险；**用户随后同意方案并授权10-D施工，最终规则、实现与迁移以[10-D施工记录](MVPB_Phase10D_Implementation_CN_v0.1.md)为准。** 当前代码基点 `main / 1eb02c4`，前一环节见 [10-C实施](MVPB_Phase10C_Implementation_CN_v0.1.md)，接续入口见 [Project_Status](../Project_Status_CN.md)。

## 1. 用户诉求与本轮已确认边界

用户要求：未来内容制作时，所有冲击强度仅填写档位；冲击削弱／免疫也按档位制度；覆盖车辆受到的所有碰撞来源，包括墙、机关、车辆、球等。

本轮用户明确选择：**所有来源的规则击退／击飞／脱球都可免疫，但保留自然推挤、撞墙阻挡和碰撞减速。** 因此目标是全来源统一规则反应，不是关闭Chaos碰撞、改变质量或保证刚体不发生任何速度／姿态变化。自然碰撞本身仍可能使车辆转动／翻倒；若以后需要绝不翻车的保护，应另行规定姿态保护效果，不能默认为冲击免疫已有该能力。

保留10-C已确认的伤害／冲击独立边界：冲击抗性不减伤，伤害抗性不降冲击；HP=0不等于已淘汰。以下具体降档算法、自然碰撞选档方式和重复触发政策仍为建议。

## 2. 推荐数据流

```text
来源产生冲击事件及来源档位
→ 目标统一冲击抗性／免疫
→ 实际受冲击档位
→ 统一响应：追加位移／姿态反应、脱球与表现
```

内容强度建议仅使用无／轻／中／重。程序仍需集中维护档位到物理速度变化／翻转等参数的响应表，否则档位不能实际驱动物理。内容作者不必为每颗球／机关填冲量或速度；底层调参人员仍能修改这张公共表，沿用已调基线后再校准。

方向与作用方式另有语义：同为重档，撞墙应根据接触法线／撞击方向产生合适反应，不能无条件使用球的飞行方向；将来推开、向上弹射、拉向中心也不可能仅由一个强度等级完整表达。默认方向由几何／动作生成；不要求每个内容作者填写一套力向量，也不在本轮提前创建大型反应样式库。

## 3. 主动攻击与普通碰撞如何只配置档位

| 来源 | 建议的档位语义 |
|---|---|
| 球／技能／机关的一次主动打击 | 固定来源档位，例如普通球中、重球重，与伤害数值／球速解耦 |
| 普通车辆互撞 | 按统一碰撞规则自动得到档位；车辆内容端配置碰撞能力档位上限 |
| 普通墙体／环境 | 默认环境策略按车辆撞击自动选档，内容端通常无需逐墙填数值；特殊墙可显式指定档位 |
| 持续接触／地面支撑／普通擦碰 | 经接触过滤通常为无，不把每帧接触报告当作一次攻击 |

这是**建议**，还需要确认普通碰撞是否随撞击强度分档。若所有墙碰撞无条件固定重档，低速蹭墙也会重档；若所有车车触碰都按车辆固定重档，堵在一起慢推也会频繁触发强反应。最少需要有意义撞击的触发过滤，推荐进一步用碰撞能力档位上限封顶，让内容配置继续保持档位制。

普通碰撞的底层测量可以使用经校准的法线接近速度／物理碰撞数据，自动映射到档位；该算法属于公共基础规则，不是每个机关各自填数值。必须区分法线撞击与沿墙切向滑动，避免高速沿墙滑行变成重击。不能直接沿用球的速度阈值、车车原始冲量阈值互相代替，也不能只从碰撞回调时已经变化的速度反推碰撞前速度。

所有物理来源都要有默认适配：普通StaticMesh墙不需要ASC或专用攻击Actor类。掉落／着地若作为冲击来源，也走同一目标抗性；正常轮地支撑不产生受击。双车碰撞分别结算每辆车收到的冲击，不用“谁是攻击者”取代对两端受力与来源能力的判定。

## 4. 目标抗性与脱球建议

建议目标使用离散降档数，伤害免疫和冲击免疫使用独立状态。示例规则为：

```text
非免疫：实际档位 = 来源档位降低目标抗性指定的档数，最低为无
冲击免疫：实际档位 = 无
```

多个Buff／Debuff的降档叠加方式、上限及是否支持负抗性仍待确认，不默认为可任意相加。档位表示离散强弱，不表示重档恰好是轻档3倍的力。

脱球依据**实际档位**与车辆的最低脱球档位比较。例如中档开始脱球：来源中、抗性降一档后实际轻，则不因该冲击脱球；来源重、降一档后实际中，则仍可脱球。无冲击永远不因本事件脱球；关闭冲击脱球应有独立配置语义，不把“最低档位=无”误解成所有碰撞都会脱球。

此处免疫保证不执行该事件的规则脱球，不禁止持有者退出、球销毁、约束失效等生命周期／安全清理。不能让原始碰撞冲量在档位结算外偷偷再触发脱球。

## 5. 必须解决的实现坑

1. **自然碰撞与追加反应重复施力**：刚体本来已产生碰撞响应，再无条件加一遍同档冲量会过度弹飞。普通物理碰撞需要计入已有响应，明确追加／补足的物理策略，再用实测定稿；不能用任意反向冲量或每帧改速度“撤销物理”。冲击免疫不承诺抵消自然碰撞。
2. **同一次球命中走两条路径**：球碰撞回调和车辆碰撞回调不能各自追加冲击／脱球。已发射球的攻击事件应与目标接触事件关联，由一个权威结果承担规则反应；自由球的自然碰撞另由物理适配处理。
3. **贴墙／连续接触反复触发**：碰撞报告可能持续产生。建议将有意义撞击与持续支撑／挤压区分，按接触事件去重／重新激活，不在每帧加档位冲量。去重以具体接触／来源为单位，不能用任意全局受击冷却吞掉其他玩家的合法攻击。
4. **墙角连锁弹射**：球击飞后撞墙可以是另一个真实事件，但不能无节制注入新能量形成墙角无限弹跳。二次碰撞判定、物理响应与再触发规则必须联合验证。
5. **旧脱球旁路**：现有`OnCollisionRootHit → BallControl.HandleVehicleCollision`直接比较原始冲量，必须迁为消费统一的实际档位结果；球／车／墙不能保留三套互相矛盾的脱球判定。
6. **网络重模拟**：游戏规则／脱球一次性结算，物理事件以帧和事件身份跟踪；物理历史重放与新伤害事件分别处理。未来GE改变抗性时，不可用客户端当前属性重算过去物理帧。GAS本身不会自动完成这项工作。
7. **保存兼容**：旧Light／Medium／Heavy序号0／1／2不能因为加入“无”而整体后移。设计档位排序应显式映射／迁移，不能直接用旧枚举数字做降档减法。

## 6. 与当前代码的关系及后续步骤

当前Resolver已将伤害与已有冲击拆开；追加冲击仍只由现有物理测量选档。车辆碰撞回调仍直接把NormalImpulse交给BallControl并比较旧阈值。10-D需要在这个基础上扩展全来源冲击适配、统一目标响应及脱球，而不只是给球新增一个Tier字段。

建议先确认：普通碰撞的“自动选档＋内容配置档位上限”、目标降档／免疫、连续接触与二次撞击政策。随后形成施工规格、保护当前DA与物理基线，再实现中央结算和来源适配；先用球／两车／普通墙／无ASC机关模拟请求验证，最后补单机、双端和网络扰动。弹簧拳的实际接入仍按此前决定等阶段10完成，不因本轮讨论自行修改。

验收至少覆盖：轻触／高速正撞／切向擦墙、静止受撞／对向移动、车车双端、连续顶墙与墙角、攻击球和自由球、重击后撞墙、普通着地／重落地、同事件双回调、降档／免疫后的追加位移和脱球、伤害不受冲击抗性影响，以及延迟／重模拟下的重复事件与收敛。

## 7. 引擎事实参考

Epic的 [Collision Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/collision-in-unreal-engine---overview) 区分刚体阻挡与Hit通知，并提示静止接触也会持续报告；因此关闭某次规则反应并不等于取消物理阻挡，接触事件也不能不经筛选地逐条当攻击。

[OnComponentHit](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Collision/OnComponentHit) 指出模拟刚体有NormalImpulse，而Sweep阻挡碰撞可为0，通用接口不能只认一个冲量字段。[Networked Physics Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/networked-physics-overview) 说明Resimulation按物理帧保存和重放历史；上述档位事件与抗性生效帧仍需项目代码明确定义。
