日期：2026-10-13。状态：**讨论草案，尚未确认待定规则、尚未施工，不代表未来技能／机关已实现。** 当前核对提交 `main / 61508961a11baef8a96376a8786561b4aee00f4c`；保留工作区内此前 HP 实测留档。依据 [10-A 规格](MVPB_Phase10A_GAS_Impact_Spec_CN_v0.1.md)和 [10-B 实施／HP 实测](MVPB_Phase10B_GAS_Foundation_CN_v0.1.md)。状态入口见 [Project_Status](../Project_Status_CN.md)。

## 1. 目标与当前缺口

统一的是服务器的命中资格和规则结算：球碰撞、技能 Trace／范围检测、机关触发和场地伤害脉冲，均可提供标准请求。检测方式、作用范围、命中频率、动作生命周期与命中后的球状态仍由对应来源管理。不要让通用结算层调用某个球的 FinishLaunch，也不要强迫机关模拟球的物理速度。

当前 `FVehicleHitContext` 已有来源、目标、归属、物理测量和事件序号；`CombatResolver` 已集中结算。但是它仍要求来源 Actor 有效、全局排除发射者，并以 `ApplyResolvedDamage` 成功作为后续冲击及球消费条件。伤害还是球的固定值，尚没有发射攻击数值快照。这些不足会妨碍攻击者退出、免疫／0 伤害命中、0 HP 目标和未来自伤技能。

10-C 沿用现有服务器权威与 GAS 唯一 HP 来源，建立正式可沿用的窄数据契约；不建设技能库、场地管理器、淘汰系统或通用事件总线。

## 2. 共用数据契约

以下类型名是建议名，编码时沿用项目命名风格。

| 数据 | 责任与内容 |
|---|---|
| AttackSourceSnapshot | 服务器生成的攻击来源实例／动作 ID、来源类别／标签、稳定玩家归属、可选 Actor／PlayerState 引用、数值模式、捕获的攻击力／动作倍率／倍率增量及明确的效果载荷 |
| CombatHitRequest | 动作 ID＋命中脉冲序号＋目标身份，目标、来源快照、命中位置／方向，可选物理测量，独立的伤害与冲击提案；没有物理碰撞也能提交合法伤害 |
| CombatHitResult | 命中是否接受／拒绝原因／是否重复，原始及防御后伤害、实际 HP 减少，独立冲击结果；预留状态效果结果。结果不以 HP 是否变化定义成功 |

来源归属、直接造成效果的 Actor 和伤害数值来源分开。例如玩家触发的机关可以记录该玩家归属，同时继续使用机关自身基础伤害；不因存在 Instigator 就自动套车辆攻击力。

来源 Actor 引用只提供有效时的上下文，不是飞行攻击成立的必要条件。快照保留在攻击实例上，目标仍须有效并具备相应接收能力。沿用玩家 PlayerState ASC 与被动车 Actor ASC，以窄目标适配接口取得 ASC／受击能力，避免要求目标必须是某个玩家 Pawn 类型。物理刚体是冲击分支的需要，不是伤害分支的必要条件。

只保存这次动作所需的效果标签／载荷，不复制攻击者全部状态标签，也不依赖已经销毁的来源重新读取数值。球仍不拥有 ASC。GAS Effect Context 保留可用来源引用及稳定归属；来源 ASC 消失后仍能在目标 ASC 上提交已保存的合法结果。

## 3. 统一流程与结果独立

```text
服务器来源：碰撞／Trace／Overlap／伤害脉冲
  → 标准请求
  → 校验来源事件、目标资格、重复请求
  → 分别结算伤害、冲击，以及后续状态效果
  → GAS 改 HP／状态；Movement 或刚体执行物理结果
  → 返回一次权威结果
  → 来源更新自身行为，表现层接收必要结果
```

- `HitAccepted` 与 `ActualHPRemoved` 独立；HP=0 不表示已淘汰。沿用已经确认的规则，0 HP 的有效冲击仍可成立。
- `ResolvedDamage` 表示防御后的伤害；`ActualHPRemoved` 是受剩余 HP 限制后的实际减少。例如 HP=10、结算伤害25，实际只扣10。计分／吸血将来可明确选择依据，不把两者混成一个字段。
- 伤害免疫仅阻止伤害分支。冲击免疫、状态免疫分别判定；完整拒绝命中是另一种目标规则，未来反射／格挡也须返回明确原因。
- 单纯伤害不要求命中法线／物理冲量；冲击则由来源提供方向及可选物理数据，无效冲击数据不凭空制造方向，也不抹掉合法伤害结果。
- 10-C 拆开伤害与**既有**冲击分支，保留旧物理选档、速度变化和翻转值。10-D 才实现完整显式档位、抗性、不同来源物理选档及最低脱球档位，保护旧枚举序号与 DA 调参。
- 来源读取结果后决定自己的生命周期：普通球消费本次攻击，范围技能继续处理其他目标，伤害区等待下一脉冲。不能把“命中就销毁来源”写在通用 Resolver 内。
- 普通球继续排除发射者；未来自伤技能须可明确允许。该过滤属于来源／动作策略，不能在共享入口永久禁止所有自伤。

核心仍为 C++。客户端只能提交动作／输入请求；命中对象、数值、事件 ID 和资格由服务器决定。HP 经 Attribute 复制，演出以后从权威命中结果产生必要 Cue／反馈，不按 HP 通知条数触发。无需复制全部内部结算数据到所有客户端。

## 4. 数值模式与捕获时间

已有确认的玩家攻击公式：

```text
RawDamage = CapturedAttackPower × max(0, ActionMultiplier + sum(MultiplierDeltas))
```

建议提供两个数据模式：`VehicleAttackScaled` 与 `SourceFixedDamage`。球／主动攻击通常使用第一种；机关默认第二种，使用其配置的基础伤害。模式由来源配置，来源类别仅用于归属／标签，避免以后玩家部署的机关不能选用车辆倍率。

建议 Combat AttributeSet 先加入 AttackPower、通用输出倍率增量（初值0）和 DamageTakenMultiplier（初值1）；动作倍率保留在动作／球的配置，动作专属增量由该动作提供。基础值由 Vehicle DA 初始化，局内 GE 影响有效属性；不把物理质量、悬挂或抓地迁入这些战斗属性。

- 飞行球在服务器接受发射时捕获攻击力、倍率、效果载荷和归属；飞行期间 Buff 到期／发射者退出不回算。
- 目标防御、受伤倍率和免疫在每次命中时读取。
- 直击技能在该次攻击成立时捕获；持续伤害的来源数值捕获时机须由效果明确定义，例如施加中毒时捕获或每次脉冲取当前值，不沿用一条隐含的“所有攻击都在发射时”规则。
- 伤害区每次伤害脉冲构造独立请求；场地固定基础伤害不需要来源 ASC。

建议本环节目标公式先为 `FinalDamage = RawDamage × max(0, DamageTakenMultiplier)`；目标伤害免疫时 FinalDamage=0。暂不引入平减护甲，未来若增加防御，集中扩展目标结算函数／GE 计算，不要求各来源修改伤害代码。**这是待确认建议，不是既定规则。** 当前简单公式在 Resolver 的共享结算函数中计算，Instant GE 只提交结果；没有必要为了接入 GAS 增加复杂 Execution Calculation。

## 5. 来源接入示例与持续效果边界

| 来源 | 如何产生请求 | 数值及生命周期 |
|---|---|---|
| 普通飞行球 | 服务器 Chaos 命中，读取该次发射快照 | 玩家攻击×动作倍率；按球自身政策消费首次接受命中 |
| 直击／范围技能 | GA 管动作许可，服务器 Trace 或范围检测逐目标提交 | 玩家攻击×技能倍率；每个目标独立结算，技能决定是否允许多段 |
| 激光／爆炸／落锤机关 | 自身触发／检测／动作时序提供请求 | 默认机关固定伤害；有配置的冲击提案；不需要机关 ASC |
| 火焰／危险地面 | 服务器定时伤害脉冲，对当前目标提交 | 每次脉冲独立；不能按每帧 Overlap 重复扣血 |
| 中毒等持续扣血 | GE 管存续／叠层，未来每次周期伤害共用伤害规则 | 目标防御每次结算；不另写绕过规则的直接 HP 修改 |
| 加速道具、减速／打滑区域 | 对目标 ASC 应用／移除持续 GE | 无伤害时不强制构造攻击命中；10-E 管效果生命周期，10-F 将有效运动参数接入物理帧历史 |

状态效果的来源身份、目标适配和免疫标签可以复用。恢复也应经独立的恢复语义与 GAS 入口，不把负伤害作为回血暗号。10-C 只落实当前伤害入口及扩展契约，实际 GA／持续 GE 和场地玩法在对应后续环节接入。

## 6. 多目标、多段与防重复

建议命中身份为“服务器来源实例／动作 ID＋脉冲序号＋目标身份”。该 ID 在攻击／脉冲成立时分配，重复物理回调沿用同一个 ID；不能每次碰撞回调都生成新 ID，导致去重失效。

- 单球一次发射对同一目标的多个组件回调只结算一次。
- 爆炸同一动作命中两个目标允许各结算一次，不能全局把整次动作标为已用后跳过其余目标。
- 连击第二段／伤害区下一脉冲是新序号，允许再次命中同一目标。
- 球的“首次接受命中后不再攻击其他目标”由球的状态规则保证，与通用逐目标去重分别承担责任。
- 去重记录与动作／脉冲生命周期配套释放，已结束事件不可重新接受；需要容量与清理策略，不创建永不清理的全局集合，也不以短超时清理来放行旧重复事件。

## 7. 本环节迁移与施工顺序

1. 确认本草案的待定规则，形成 10-C 施工规格；保留 10-B 尚待完成的回归，不把讨论视作全部验收。
2. 实现标准请求／结果、来源快照、窄目标适配与事件去重，先验证非球来源及无物理数据的纯伤害请求。
3. 接入 Combat AttributeSet 与统一目标伤害结算；移除以扣血成功决定整体命中成立的耦合，沿用现有冲击结果。
4. 球发射捕获快照，命中读取快照；迁移当前 DA 配置，保持普通球仍为25伤害，现有 HP、控球、后坐及物理参数不重调。
5. 补服务器事件 ID、来源模式、RawDamage／ResolvedDamage／ActualHPRemoved 等可关闭日志和 HUD 必要信息；仅从结果触发一次演出。
6. 编译／自动化、单机和双端回归后记录证据，再由用户指定进入 10-D。

迁移推荐校准为“玩家 AttackPower=25、普通球 ActionMultiplier=1、输出增量0、目标受伤倍率1”，保留旧固定25字段作迁移核对。新公式启用须有明确迁移标记／配置版本，团队手工填写并验证；不能凭新增 C++ 字段默认值假装旧资产已迁移，也不能把旧伤害25误当倍率25。编码前具体固定过渡策略；不保留两套运行时 HP。

本环节自动化应覆盖：普通球25基线、无来源 ASC 的固定伤害、无物理信息的纯伤害、0伤害与0HP的有效命中、伤害免疫不误挡冲击、攻击者离开／Buff到期不改飞行数值、目标命中时防御、多目标／多脉冲／重复回调，以及剩余HP小于伤害时的实际扣血。自动化可用明确的机关／技能模拟请求验证入口，不代表真实机关／技能已开发。团队再测两方向命中、控球／冲击及约100ms RTT复制收敛。
