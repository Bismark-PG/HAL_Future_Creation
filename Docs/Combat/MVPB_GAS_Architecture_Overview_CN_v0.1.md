## 一页概览

本游戏的核心仍是**驾驶、抢球、控球和主动击球**。GAS（Gameplay Ability System）提供统一的“数值与状态规则层”：车辆的 HP、攻击能力、技能许可、Buff／Debuff、持续时间、叠层、免疫和表现事件。现有 Chaos 刚体和自定义街机移动负责实际运动；球的 `Free / Controlled / Launched` 状态、飞行、碰撞和网络物理也继续由其 Actor／组件管理。

> **GAS 决定这一下能否发动、携带什么规则、目标受到什么结果；服务器物理系统决定车和球如何真实移动与碰撞。**

引入 GAS 的目的不是“把物理改写成技能”，而是让未来的加速道具、减速区域、重球、撞击抗性和角色技能使用可追踪、可配置、可复制的规则，避免每增加一个内容就往车辆或球碰撞回调里添分支。[Epic 的 GAS 概览](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-the-unreal-engine-gameplay-ability-system)将 ASC、Attribute、Ability、Effect 和 Cue 分别用于能力所有权、数值、动作、效果和表现；本项目依照这些职责做轻量接入。

## 1. 为什么当前工程需要 GAS

两人Listen Server的驾驶、球权、发射和命中已经有可继续演进的权威链路。原10-A／10-B时期，固定伤害、扣血与击退耦合、独立脱球冲量阈值等问题推动了此次接入；这些历史问题已在10-C／10-D按独立伤害／冲击与档位规则重构，不再将HP=0视为冲击无效。历史背景见[10-A规格](MVPB_Phase10A_GAS_Impact_Spec_CN_v0.1.md)，当前限制与实测边界见项目状态。

正式开发会出现不同车辆基础攻击、球或技能动作倍率、0 伤害强冲击、受击抗性、持续减速、打滑区、重球、场地机关以及死亡和观战。它们需要共同的来源、目标、持续时间和结算语义。GAS 适合管理数值与状态生命周期；`CombatResolver` 仍是服务器唯一的标准命中入口，负责把物理事实、攻击快照、伤害和冲击规则接起来。普通车辆互撞仍主要改变位置和球权，不自动成为主要伤害来源。

## 2. 先认识五个 GAS 概念

| 概念 | 本项目中的含义 | 例子 |
|---|---|---|
| ASC（Ability System Component） | 某个战斗单位所拥有的技能、效果、标签和属性入口 | 玩家 `PlayerState` 持有 ASC，当前车辆 Pawn 是它的 Avatar |
| Attribute / AttributeSet | 需要在游戏中结算、改变或复制的数值；分组保持职责清楚 | 当前 HP、最大 HP、基础攻击、之后确有需要的运动倍率 |
| GA（Gameplay Ability） | 主动动作的许可、消耗、冷却、阶段与触发 | 玩家主动使用加速技能，先检查能否发动，再施加持续效果 |
| GE（Gameplay Effect） | 一次性或持续的数值／状态变化，包含持续时间与叠加策略 | 受伤扣 HP、加速 5 秒、进入冰面期间低抓地 |
| Gameplay Tag / Cue | Tag 表示可查询的规则状态；Cue 负责音效、视觉等表现 | `State.Slippery` 表示打滑；轮胎火花或提示音由 Cue／表现层播放 |

不是每个效果都需要 GA。场地机关可以由服务器在进入／离开时直接给目标施加或移除 GE；玩家主动技能通常由 GA 发起。Gameplay Cue 只承载表现，不能作为服务器命中、HP 或球权的依据。[Epic 的 GAS 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-the-unreal-engine-gameplay-ability-system)说明 Cue 可能不可靠到达，因此权威规则必须由可靠的游戏状态决定。

## 3. 系统归属和数据流

```text
玩家输入 ─→ PlayerController ─→ GA 许可／请求 ─→ ASC (PlayerState)
                                   │                  │
                                   │                  ├─ Attribute / GE / Tag
                                   │                  └─ 状态与结果复制
                                   └─ 可执行的车辆动作请求

车辆输入历史 ─→ ArcadeVehicleMovementComponent ─→ Chaos 刚体
球状态与碰撞 ─→ BasicBallActor / BallControlComponent ─→ 服务器命中事实
技能／机关事件 ────────────────────────────────┘
                                               ↓
                                      CombatResolver
                                      ├─ 命中资格与去重
                                      ├─ 独立伤害结算 → 目标 GAS HP
                                      ├─ 独立冲击档位 → 车辆物理结果
                                      └─ 脱球／一次性球状态消费
```

玩家 ASC 的长期 Owner 放在 `PlayerState`，车辆 Pawn 是随出生和控制关系变化的 Avatar。Pawn 更换或离场时，要重新绑定／清理 Avatar，但不从 UI 或球 Actor 直接改玩家 HP。无玩家归属的被动测试车辆若需要继续受同一战斗规则影响，可由自身持有 ASC；普通球、道具和机关默认不持有 ASC。球只保存轻量的攻击来源与效果载荷，保证多球场景下不会为每颗物理球建立一套技能系统。

服务器拥有命中、HP、Buff、球状态、淘汰和最终物理结果的决定权。客户端可以提交自己合法的输入／技能请求和做有限的本地反馈，不能提交“我打中了谁”或“造成多少伤害”。ASC 的预测与现有 Network Physics 车辆重模拟是两件事：能预测 GA 激活，不代表车辆施力参数会自动随重模拟回放。

## 4. 车辆属性：哪些属于 GAS，哪些继续留在 DA

**原则：Data Asset 定义车辆出厂基线；GAS 管局内会变化、会结算或需要状态复制的量。** 不把每一个 C++ 浮点数都改成 Attribute，也不让技能直接改车体质量、碰撞形状或惯性张量。

| 类别 | 建议位置 | 说明 |
|---|---|---|
| 当前 HP、最大 HP | GAS AttributeSet；最大 HP 的初始化种子可来自 Vehicle DA | 接入后只有一份权威当前 HP；旧 Health 组件若继续给 UI 用，只读映射 GAS 值 |
| 车辆基础攻击力 | 车辆配置提供基础值，战斗Attribute保存生效值 | 10-C已有AttackPower及输出倍率增量；发射时捕获生效值，飞行期间到期不回算 |
| 目标防御、受伤倍率、伤害免疫 | GAS Attribute／Tag／GE | 10-C已有受伤倍率／伤害免疫，命中时判定；本阶段无平减护甲，公式见10-C实施 |
| 冲击抗性、最低脱球档位 | 车辆／战斗配置给基础规则；临时状态可由 GAS 影响 | 源档位与目标实际承受档位分开记录；重车可以不因弱档脱球 |
| 质量、碰撞体、基础加速／速度／抓地／转向 | VehicleDefinition／Movement 配置 | 当前已调参数是权威基线；不能由新 C++ 默认值覆盖 |
| 临时加速、减速、低抓地倍率 | 需要时用 GE／少量运动修饰 Attribute 或等价状态 | 只改变物理组件使用的有效参数；持续与叠加由 GAS 管，真正施力仍在移动组件 |
| 当前油门、刹车、转向、手刹输入；车速、位置 | 原输入历史／Chaos 物理 | 属于高频模拟数据，不建成每帧更新的 GAS Attribute |
| 摄像机、Mesh、轮胎外观 | Local DA／表现层 | 不参与战斗权威结算；不要为了统一配置而迁入 GAS |

当前保存基线的玩家车是 `MaxHP=100`、质量覆盖 `800 kg`、前进加速度 `1800 cm/s²`、前进速度上限 `2400 cm/s`；普通球命中固定伤害 `25`。这些只是 10-A 的**现有资产值**，并非新系统强制的所有车辆默认值。完整字段与哈希见[基线快照](MVPB_Phase10A_Baseline_20260930.json)。

### 运动效果的关键边界

以加速道具为例：服务器给车辆 ASC 加一个持续 GE，使“有效加速度倍率”和“有效速度上限倍率”改变；移动组件以 `Vehicle DA 基线 × 当前有效倍率` 在物理步施力。打滑区类似，主要降低现有侧向抓地相关参数，而不是直接给车辆瞬移或简单关闭 Chaos 碰撞。若效果是一次性爆炸推开／冲刺，则由服务器授权一个明确的物理冲量动作，而不是让 GE 每帧设置位置。

这些有效倍率必须在服务器和拥有客户端的车辆物理历史中按相同帧取得，重模拟时重放当时的倍率；单纯复制最新Attribute、却用它重新计算过去所有帧，会产生客户端回拉。运动桥接列在10-F，开发拆分、首例测试方案、未定帧同步规则与跨设备入口见[10-F计划](MVPB_Phase10F_Movement_Effects_Plan_CN_v0.1.md)。必须用双人Listen Server和延迟测试验证，不能只凭GAS单机生效就宣布完成；F2已实现该桥接并以原生夹具GE完成初步双端／迟到／恢复检查，详见[F2实施](MVPB_Phase10F2_Implementation_CN_v0.1.md)；F3正式5秒GE与选择性清除已完成并验证真实Owner请求／刷新／自然到期；F4完整网络／真人物理验收待完成。

## 5. 伤害入口与冲击入口彼此独立

玩家主动攻击采用已确认的语义：

```text
原始伤害 = 发动时锁定的车辆基础攻击力
         × max(0, 此动作倍率 + 若干可正可负的倍率增量之和)
```

例如基础攻击 `20`、动作倍率 `1.25`、额外增量 `+0.25`，则原始伤害为 `30`；这只是公式示例，不改变当前普通球的 `25` 点保存值。场地机关使用**机关自己的基础伤害**，不自动继承车辆攻击力。目标防御、受伤倍率和免疫在命中时读取；防御的精确运算顺序仍是阶段 10-C 前需定稿的规则。

冲击提案可由物理测量选档，也可由球／技能／机关明确指定 `None / Light / Medium / Heavy`。例如“0 伤害但 Heavy 冲击”的推开机关，或“高伤害但 Light 冲击”的精准技能，均通过同一标准命中入口表达。目标抗性可以降低／阻断实际冲击；目标的最低脱球档位单独决定球权反应。普通车车相撞仍可物理推动和脱球，默认不通过这条管线额外扣 HP。

当前球的物理选档使用等效速度，Combat DA 保存中档阈值 `1000 cm/s`、重档 `2600 cm/s` 和三档物理结果。当前持球脱落却用原始碰撞冲量 `100000` 作独立阈值。两者的输入量尺不同；阶段 10-D 会统一**档位结果与目标反应**，并通过碰撞实测校准脱球映射，不能把 `100000` 直接除以球的速度阈值来“推导”档位。

在正式淘汰状态加入前，`HP=0` 仍能受有效冲击；最终伤害为 `0` 也不能令命中被误判无效。将来“已淘汰”是否还能被攻击，由独立比赛状态规则决定，而不是从 HP 数字暗中推断。

## 6. 为什么飞行球要在发射时保存攻击快照

服务器接受发射时，球记录稳定玩家来源、动作／发射序号、效果标签、车辆当时的攻击值和倍率。球飞行途中发射者退出或攻击 Buff 到期，这次发射的攻击数值**不倒退改变**；服务器命中时再读取目标当时的防御和免疫。球的控制状态仍只有 `Free / Controlled / Launched` 一份权威快照，攻击载荷不创造第二个可碰撞的球。

命中按“来源 Actor 身份＋服务器事件序号”去重。重复物理回调或网络重发只能消费这次球命中一次，不能二次伤害、二次击飞或二次切换球状态。球归属的稳定玩家 ID 用于日后计分、击杀归属和断线后结算；当前仍可保留当时 Pawn 引用作表现辅助，但它不是唯一来源。

## 7. 扩展新内容时怎么放置规则

| 新内容 | 数据与规则放置方式 | 不应做的事 |
|---|---|---|
| 新车辆 | Vehicle DA 放基础物理和外观、基础战斗种子；GAS Attribute 管局内 HP／攻击等 | 在车辆蓝图 Tick 自行扣血或修改碰撞体质量做 Buff |
| 新球／重球 | Ball DA 放球物理、动作倍率和冲击来源策略；发射时生成轻量载荷 | 给每颗球挂 ASC，或让客户端自行申报命中伤害 |
| 主动技能 | GA 管发动条件、资源、冷却和阶段；产生标准动作／命中请求或施加 GE | GA 逐帧驾驶车辆／逐次求解球弹跳 |
| 加速道具／减速区／打滑区 | 服务器触发 GE 的添加／移除；运动倍率通过物理历史进入移动组件 | 仅在主机改参数，拥有客户端仍按旧参数预测 |
| 场地机关 | 机关自己的伤害基础值、冲击档位和触发状态；提交同一标准命中请求 | 借用“最近玩家攻击力”，或绕开 Resolver 直接改目标 HP |
| 受击抗性／护盾 | GAS 状态参与目标结算；伤害免疫与冲击免疫分开声明 | 用“伤害为 0”间接阻止物理冲击 |
| 淘汰、观战、结算 | GameMode／GameState／PlayerState 的比赛规则，并引用 GAS 结果 | 把 `HP=0` 直接等同于完整死亡和胜负结算 |

Gameplay Tags 应表达稳定的规则概念，如打滑、受伤免疫、冲击抗性或技能禁用；具体命名、叠加与互斥关系随对应能力落地时登记在配置规范中，不在本概览里预造整套标签树。Gameplay Cues 用于可读的发光、音效、UI 提示，结果仍取权威 Attribute、球状态和事件。

GAS 使用 UE 5.8 自带的 `GameplayAbilities` 插件。启用状态在 `.uproject`，模块依赖在 `Build.cs`；这些配置、项目 C++ 和项目内资产可以提交 Git。组员需使用统一的 UE 补丁版本并在本机编译；不把引擎插件自身、`Binaries/` 或 `Intermediate/` 上传为项目实现。
