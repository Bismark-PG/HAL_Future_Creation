## 1. 主要结论

1. **当前确实存在材质回弹**：车辆、地面和墙面均走引擎默认物理材质，Restitution=0.3；项目合并模式为Average。独立Solver读取的实际车辆／地面材质与保存配置判断一致。
2. **长时间运动还包含接地摇摆／翻滚**：重翻对照中，触地后约95.8%的样本碰撞体最低点已在地面±1cm内；将恢复系数降为0后，这个比例约100%，但仍约9.63秒才进入严格低速稳定。它不能只用“弹性太大”解释，也不能用压低所有Z速度解决。
3. **低回弹之后还要审查环境规则追加**：默认材质的本次重翻工况中追加为0；零回弹对照加入现有补量公式后，出现约6.50cm额外离地间隙，累计追加速度约129.52cm/s。这个受控结果证明两个通道存在相互作用，不能断言它就是玩家原局的主因。
4. **当前几何会影响碰撞姿态**：车辆物理代理为456×288×269cm，测试墙体总高100cm、露出地面约50cm。受控短墙工况最大倾角约12.84°；只升高墙面的对照约0.02°。较低接触点会影响Pitch，不能只改弹性。
5. **侧翻仍可驾驶的源码缺口保持明确**：普通接地仍是单条世界向下射线，未把车身姿态与有效轮侧支撑纳入普通驾驶门控；已有姿态条件只作用于脱墙辅助。本轮尚未改变这条执行路径。

## 3. 对照方法与结果

加载保存玩家DA及Combat DA，在独立临时Game World中建立相同车辆凸包／BodyInstance及测试地面；不开普通油门／抓地／转向或落地辅助。物理线程以TaskGraph执行，每组720个1/60秒步，16组共11520份姿态／速度样本，收集2701份按另一接触体合并的原生接触记录。

四个工况分别为：水平放置且底部离地500cm下落；初始姿态Pitch20°／Roll15°、V=(450,0,750)cm/s、W=(0,5.13,0.7)rad/s的重翻；以1400cm/s撞保存高度短墙；只将墙总高改为500cm的临时高墙对照。重翻是接近Heavy参数的受控初值，未实际发动球／机关攻击。

每个工况做四种组合：保存材质／零回弹材质 × 仅自然物理／带接触规则补量。零回弹材质只是在运行实例上使用临时副本，Restitution=0、OverrideCombine=Min，摩擦保留；没有创建保存材质或修改球／地面／墙资产。

规则对照使用原生Chaos法向冲量、现有`HALImpact::PhysicalSupplement`与真实`ApplyAction_Internal`；接触回合资格在夹具内按相同间隔建模，追加在下一物理步执行。它**不包含完整ASC／抗性／脱球、OnComponentHit派发、网络帧调度和RPC链**，不冒充真人日志或完整联机测试。

## 4. 建议的最小修正入口

下一小步先保持质量、驾驶力、技能击飞及档位／脱球规则，分别验证：

1. **车辆专用低回弹材质**：以Restitution=0、Min合并作为首个对照起点，摩擦暂保持现值。通过共享车辆规则DA引用材质或明确的根Body覆盖应用入口统一配置，提供团队Editor步骤；材质资产尚未创建。车球接触也受双方合并影响，须回归球权／Free球和主动命中，不能只测车与地面。
2. **支撑／落地与墙面冲撞分开处理追加**：普通支撑／落地应避免反复注入额外向上补量，水平墙撞保留既有有界响应，球／机关显式击飞保留。具体筛选门槛及是否调整某类落地规则在实现规格中明确；不顺带改伤害、免疫、有效档位或脱球语义。
3. **核对车辆代理与墙面接触高度**：当前代理厚度接近宽度，不符合扁平车身的直觉；通过临时几何／实机对照选择合理厚度、参考位置和墙面碰撞高度。保存资产由团队手工生成／引用，代理不直接改uasset，不静默恢复某个旧碰撞体。
4. **摇摆与翻车按不同目标收敛**：普通落地的有限耗散／辅助与低速长按自救分开。若材质／接触修正后仍有不合理摇摆，单列有限落地辅助规格；不加入常驻自动扶正或瞬间清空所有角速度。

然后推进计划中已确认的姿态操控限制／自救，再返回VP-2～4。新增共享DA参数与时长仍按已确认规则提供，全局资产／Input接线在相应代码完成后交团队手工配置。

## 5. 另两项表现配置复核

保存表现DA的RelativeTransform为单位变换，四轮RadiusCm均为10cm；先前已导入模型的真实半径约47.5cm、最低点约本地Z=0。当前物理根底部为本地Z=-134.5cm，平地静止时其中心约高于地面134.5cm。

按这些保存值且总缩放1推导，模型轮底与物理支撑面存在约134.5cm参考高度差，滚动半径也不匹配。这是**配置推导，未做本轮画面验收**；应在最终代理尺寸确定后同步核对模型相对位置及世界轮半径，不用改物理速度掩盖轮转问题，也不据此撤销用户的VP-1阶段结束确认。实际游戏若有额外实例覆盖，先核对覆盖。
